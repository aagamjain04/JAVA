## 1. Map Overview

### Hierarchy

```
Map<K,V>  (interface)
├── HashMap
│   └── LinkedHashMap
├── TreeMap  (implements NavigableMap → SortedMap → Map)
├── Hashtable  (legacy, synchronized)
└── ConcurrentHashMap
```

### Comparison at a Glance

|Class|Order|Null Key|Null Value|Thread-Safe|Get/Put|
|---|---|---|---|---|---|
|`HashMap`|None|1 allowed|Yes|No|O(1) avg|
|`LinkedHashMap`|Insertion / Access|1 allowed|Yes|No|O(1) avg|
|`TreeMap`|Sorted (natural / Comparator)|No|Yes|No|O(log n)|
|`Hashtable`|None|No|No|Yes (legacy)|O(1) avg|
|`ConcurrentHashMap`|None|No|No|Yes|O(1) avg|

### Key API Methods

```java
// Read
map.get(key)                    // O(1), returns null if missing
map.getOrDefault(key, default)  // safe, no NPE
map.containsKey(key)            // O(1)
map.containsValue(val)          // O(n) — scans all values

// Write
map.put(key, value)             // insert or update
map.putIfAbsent(key, value)     // insert only if key missing
map.remove(key)                 // delete
map.replace(key, value)         // update only if key exists

// Iterate (prefer entrySet — avoids double lookup)
for (Map.Entry<K,V> e : map.entrySet()) { ... }
map.keySet()
map.values()

// Java 8+
map.computeIfAbsent(key, k -> new ArrayList<>())
map.merge(key, 1, Integer::sum)
map.forEach((k, v) -> System.out.println(k + "=" + v))
map.getOrDefault(key, defaultValue)
```

## 2. HashMap Internals

### How `put(key, value)` Works — Step by Step

**Step 1 — hashCode()**

```java
int h = key.hashCode();
// HashMap applies a secondary "spread" hash to reduce clustering:
hash = h ^ (h >>> 16);
```

**Step 2 — Index Calculation**

```java
int index = (n - 1) & hash;
// n = array capacity (default 16, always power of 2)
// Bitwise AND is faster than % and works correctly for power-of-2 sizes
```

**Step 3 — Collision Handling**

- If the bucket is empty → place a new `Node` there.
- If the bucket is occupied → walk the chain using `.equals()`:
    - Key match found → **update** the value.
    - No match → **append** a new `Node` to the chain.

**Step 4 — Treeify (Java 8+)**

- When a single bucket chain exceeds **8 nodes** AND the table has **≥ 64 slots**, the linked list converts to a **Red-Black Tree**.
- Worst-case lookup goes from O(n) → **O(log n)**.
- The tree reverts to a linked list when it shrinks below **6 nodes**.

**Step 5 — Resize**

- When `size > capacity × loadFactor` (default: `16 × 0.75 = 12`), the array **doubles** in capacity.
- All entries are **rehashed** into the new array — expensive, O(n).

### Bucket Array Visualised (capacity = 16)

```
index | contents
------+------------------------------------------------------------
  [0] | null
  [1] | Node("a", 1) → Node("q", 9)   ← collision chain
  [2] | null
  [3] | Node("name", "Alice")
  [4] | null
  ... | ...
 [15] | null
```

### Node Structure (simplified)

```java
static class Node<K,V> {
    final int    hash;
    final K      key;
    V            value;
    Node<K,V>    next;   // linked list pointer for chaining
}

// Java 8+ treeified bucket uses:
static final class TreeNode<K,V> extends LinkedHashMap.Entry<K,V> {
    TreeNode<K,V> parent, left, right;
    boolean red;
    // ... Red-Black Tree rotation methods
}
```

### Key Constants

|Constant|Value|Notes|
|---|---|---|
|Default initial capacity|`16`|Always a power of 2|
|Default load factor|`0.75`|Resize at 16 × 0.75 = 12 entries|
|Treeify threshold|`8`|List → Red-Black Tree|
|Untreeify threshold|`6`|Tree → List on removal|
|Min treeify capacity|`64`|Table must be this big before treeifying|

### Why Power-of-2 Capacity?

`(n-1) & hash` is equivalent to `hash % n` only when `n` is a power of 2. The bitwise AND is **significantly faster** than modulo division. When `n = 16`, `n-1 = 15 = 0b1111`, which acts as a perfect bitmask over the lower 4 bits of the hash.

### hashCode + equals Contract — CRITICAL

- If `a.equals(b)` → `a.hashCode() == b.hashCode()` **must** hold.
- The reverse is **not required** (collisions are fine).
- If you override `equals()`, you **must** override `hashCode()`.
- Using **mutable objects as keys** is dangerous — mutating the key changes its hash, so the entry lands in the wrong bucket and becomes unreachable (effective memory leak).

```java
// BAD — mutable key
List<Integer> key = new ArrayList<>(List.of(1, 2));
map.put(key, "value");
key.add(3);              // hash changes → map.get(key) returns null!

// GOOD — immutable key
String key = "hello";   // String caches hashCode, immutable
```

### Why String is the Ideal HashMap Key

1. **Immutable** — hash cannot change after insertion.
2. **Caches hashCode** — computed once, reused forever.
3. **Correct `equals()`** — compares content, not reference.

## 3. LinkedHashMap

- Extends `HashMap` — adds a **doubly-linked list** running through all entries.
- Two ordering modes:
    - **Insertion order** (default) — entries iterate in the order they were added.
    - **Access order** — constructor `LinkedHashMap(cap, loadFactor, true)` — moves accessed entries to the tail (LRU behaviour).
- Same O(1) get/put as HashMap, slightly higher memory per entry.

### LRU Cache Implementation

```java
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity; // auto-evict oldest entry
    }
}

// Usage
LRUCache<Integer, String> cache = new LRUCache<>(3);
cache.put(1, "a");
cache.put(2, "b");
cache.put(3, "c");
cache.get(1);    // access 1 → moves to tail
cache.put(4, "d"); // evicts 2 (least recently used)
```

## 4. TreeMap

- Backed by a **Red-Black Tree** (self-balancing BST).
- All operations are **O(log n)**.
- Keys must implement `Comparable` OR you must supply a `Comparator`.
- Does **not** allow null keys (would break comparisons).
- Implements `NavigableMap` → gives powerful range-query methods.

### NavigableMap Methods

```java
TreeMap<Integer, String> tm = new TreeMap<>();
tm.put(1, "one"); tm.put(5, "five"); tm.put(10, "ten");

tm.firstKey();          // 1
tm.lastKey();           // 10
tm.floorKey(7);         // 5  — largest key ≤ 7
tm.ceilingKey(7);       // 10 — smallest key ≥ 7
tm.lowerKey(5);         // 1  — strictly less than 5
tm.higherKey(5);        // 10 — strictly greater than 5

tm.headMap(5);          // {1=one}          exclusive of 5
tm.headMap(5, true);    // {1=one, 5=five}  inclusive of 5
tm.tailMap(5);          // {5=five, 10=ten}
tm.subMap(1, 10);       // {1=one, 5=five}  [1, 10)
tm.subMap(1, true, 10, true); // {1=one, 5=five, 10=ten}

tm.descendingMap();     // reversed view
tm.pollFirstEntry();    // remove and return smallest
tm.pollLastEntry();     // remove and return largest
```

### Custom Comparator

```java
// Reverse order map
TreeMap<String, Integer> reversed = new TreeMap<>(Comparator.reverseOrder());

// Sort by string length, then alphabetically
TreeMap<String, Integer> byLen = new TreeMap<>(
    Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder())
);
```

## 5. ConcurrentHashMap

- Thread-safe without locking the whole map.
- **Java 7**: divided into `Segments` (16 by default), each an independent lock.
- **Java 8+**: per-bucket CAS (Compare-And-Swap) + `synchronized` only on the first node of a bucket. Much finer granularity.
- Does **not** allow null keys or null values (would be ambiguous in concurrent contexts).
- `size()` is approximate under concurrent modification.

```java
ConcurrentHashMap<String, Long> chm = new ConcurrentHashMap<>();

// Atomic increment — thread-safe
chm.merge("hits", 1L, Long::sum);

// compute is atomic
chm.compute("count", (k, v) -> v == null ? 1L : v + 1);

// putIfAbsent — returns existing value if key present
chm.putIfAbsent("key", expensiveComputation());

// Better alternative — only computes if absent
chm.computeIfAbsent("key", k -> expensiveComputation());
```

## 6. Set Overview

### Hierarchy

```
Set<E>  (interface, extends Collection)
├── HashSet
│   └── LinkedHashSet
├── TreeSet  (implements NavigableSet → SortedSet → Set)
├── EnumSet  (abstract, backed by bit vector)
└── CopyOnWriteArraySet  (thread-safe)
```

### Comparison at a Glance

|Class|Order|Null|Thread-Safe|Complexity|Backed By|
|---|---|---|---|---|---|
|`HashSet`|None|1 allowed|No|O(1) avg|`HashMap`|
|`LinkedHashSet`|Insertion order|1 allowed|No|O(1) avg|`LinkedHashMap`|
|`TreeSet`|Sorted|No|No|O(log n)|`TreeMap`|
|`EnumSet`|Enum declaration order|No|No|O(1) bitset|`long[]`|
|`CopyOnWriteArraySet`|Insertion|Yes|Yes|O(n) write|`CopyOnWriteArrayList`|

### Set Operations

```java
Set<Integer> a = new HashSet<>(Arrays.asList(1, 2, 3));
Set<Integer> b = new HashSet<>(Arrays.asList(2, 3, 4));

// Union — {1, 2, 3, 4}
Set<Integer> union = new HashSet<>(a);
union.addAll(b);

// Intersection — {2, 3}
Set<Integer> inter = new HashSet<>(a);
inter.retainAll(b);

// Difference (a - b) — {1}
Set<Integer> diff = new HashSet<>(a);
diff.removeAll(b);

// Symmetric difference — {1, 4}
Set<Integer> symDiff = new HashSet<>(union);
symDiff.removeAll(inter);
```

## 7. HashSet Internals

`HashSet` is literally a `HashMap<E, PRESENT>` where `PRESENT` is a static dummy `Object`:

```java
// Inside java.util.HashSet source
private transient HashMap<E, Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null; // key = element, value = dummy
}

public boolean contains(Object o) {
    return map.containsKey(o);
}
```

All HashMap rules apply:

- `hashCode()` + `equals()` contract must hold.
- One null element allowed (maps to the null-key bucket).
- No guaranteed iteration order.
- Not thread-safe.

## 8. TreeSet & LinkedHashSet

### TreeSet

- Backed by `TreeMap<E, Object>` — same Red-Black Tree structure.
- All elements must be mutually comparable.
- Implements `NavigableSet`:

```java
TreeSet<Integer> ts = new TreeSet<>(List.of(1, 3, 5, 7, 9));

ts.first();         // 1
ts.last();          // 9
ts.floor(6);        // 5  — largest element ≤ 6
ts.ceiling(6);      // 7  — smallest element ≥ 6
ts.lower(5);        // 3  — strictly less than 5
ts.higher(5);       // 7  — strictly greater than 5
ts.headSet(5);      // [1, 3]
ts.tailSet(5);      // [5, 7, 9]
ts.subSet(3, 8);    // [3, 5, 7]
ts.pollFirst();     // removes and returns 1
ts.pollLast();      // removes and returns 9
```

### LinkedHashSet

- Extends `HashSet`, backed by `LinkedHashMap`.
- Maintains **insertion order** with O(1) operations.
- Most common use case: **deduplicate a list while preserving order**:

```java
List<Integer> list = Arrays.asList(3, 1, 4, 1, 5, 9, 2, 6, 5);
List<Integer> deduped = new ArrayList<>(new LinkedHashSet<>(list));
// [3, 1, 4, 5, 9, 2, 6]
```

### EnumSet

- Backed by a `long` bit vector (or `long[]` for > 64 enum values).
- All operations are O(1) using bitwise ops — fastest Set for enums.
- Cannot hold null.

```java
enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }

EnumSet<Day> weekend  = EnumSet.of(Day.SAT, Day.SUN);
EnumSet<Day> weekdays = EnumSet.complementOf(weekend);
EnumSet<Day> all      = EnumSet.allOf(Day.class);
EnumSet<Day> none     = EnumSet.noneOf(Day.class);
```

### Two Sum — O(n) with HashMap

```java
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>(); // value → index
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (seen.containsKey(complement))
            return new int[]{seen.get(complement), i};
        seen.put(nums[i], i);
    }
    return new int[]{};
}
```

### First Non-Repeating Character

```java
char firstUnique(String s) {
    Map<Character, Integer> freq = new LinkedHashMap<>();
    for (char c : s.toCharArray())
        freq.merge(c, 1, Integer::sum);
    for (Map.Entry<Character, Integer> e : freq.entrySet())
        if (e.getValue() == 1) return e.getKey();
```

### LRU Cache (LinkedHashMap)

```java
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder = true
        this.capacity = capacity;
    }

    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {

        cache.put(2, "b");
```

## 10. Interview Questions

### HashMap Internals

**Q1. How does HashMap handle hash collisions?**

> Uses separate chaining — each bucket is a linked list. Java 8+ converts a bucket to a Red-Black Tree when the chain exceeds 8 nodes AND the table has ≥ 64 slots. This reduces worst-case lookup from O(n) to O(log n).

**Q2. What happens when two keys have the same hashCode?**

> They land in the same bucket. `equals()` is then used to check whether it's the same logical key (update value) or a different key (append new node to the chain).

**Q3. Why does HashMap capacity stay a power of 2?**

> Allows index calculation as `(n-1) & hash` (bitwise AND) instead of costly modulo `%`. This only produces a valid uniform distribution when n is a power of 2, since `n-1` forms an all-ones bitmask over the lower bits.

**Q4. What is the default load factor and why 0.75?**

> 0.75 is a deliberate balance — lower load factor means more resizes (wasted memory/time), higher load factor means more collisions (slower lookup). 0.75 was chosen empirically to keep both time and space overhead acceptable.

**Q5. What is the purpose of `hash = h ^ (h >>> 16)` in HashMap?**

> Called "spread hashing." It XORs the upper 16 bits of the hash down into the lower 16 bits. This ensures that high-bit variation still influences the bucket index, reducing clustering in small tables.

**Q6. Why is String an ideal HashMap key?**

> Three reasons: (1) Immutable — the hash can never change. (2) Caches `hashCode` — computed once on first call, stored in a private field. (3) Correct `equals()` — compares character content, not reference.

**Q7. What happens if you use a mutable object as a HashMap key and then mutate it?**

> The key's `hashCode()` changes, so the entry now lives in the wrong bucket. `get()` won't find it — the entry is effectively lost and cannot be removed. Always use immutable objects as map keys.

**Q8. What is the difference between HashMap and Hashtable?**

> `Hashtable` is legacy (Java 1.0), synchronizes every method (slow), disallows null keys and values. `HashMap` is unsynchronized, faster, allows one null key and multiple null values. For thread safety, prefer `ConcurrentHashMap` over `Hashtable`.

---

### Concurrency

**Q9. How does ConcurrentHashMap differ from HashMap and Hashtable?**

> `HashMap` is not thread-safe. `Hashtable` synchronizes every method — only one thread can access the map at a time. `ConcurrentHashMap` (Java 8+) uses per-bucket CAS and synchronized only on the first node of a bucket, allowing concurrent reads and even concurrent writes to different buckets. `size()` is approximate under concurrent modification.

**Q10. Why doesn't ConcurrentHashMap allow null keys or values?**

> In a concurrent context, `get(key) == null` is ambiguous — does the key not exist, or does it map to null? This ambiguity complicates atomic operations. HashMap can resolve it with `containsKey()`, but that's not atomic in a concurrent map.

---

### LinkedHashMap / TreeMap

**Q11. How do you implement an LRU cache in Java?**

> Extend `LinkedHashMap` with constructor argument `accessOrder=true` and override `removeEldestEntry()` to return `true`when `size() > capacity`. Alternatively, combine a `HashMap` with a `Deque` manually for more control.

**Q12. When would you choose TreeMap over HashMap?**

> When you need: (a) sorted iteration of keys, (b) range queries (`subMap`, `headMap`, `tailMap`), or (c) nearest-key lookups (`floor`, `ceiling`, `lower`, `higher`). TreeMap costs O(log n) vs O(1), so only use it when ordering matters.

---

### Set

**Q13. How does HashSet ensure uniqueness?**

> It is backed by a `HashMap`. Elements are stored as keys, all mapped to a shared dummy `PRESENT` object. Since map keys are unique, duplicates are silently dropped. `add(e)` returns `false` if the element already existed.

**Q14. Can you store null in a HashSet? What about TreeSet?**

> `HashSet` allows exactly one null (stored in the null-key bucket of its backing HashMap). `TreeSet` throws `NullPointerException` because it calls `compareTo()` on elements — null cannot be compared unless you provide a null-safe `Comparator`.

**Q15. When would you use EnumSet over HashSet?**

> When the elements are all from the same enum type. `EnumSet` is backed by a bit vector (a `long` or `long[]`), making all operations O(1) with no boxing overhead — the fastest Set implementation in the JDK.

## Quick Reference Cheat Sheet

```
Pick HashMap when:       default choice, O(1), unordered
Pick LinkedHashMap when: need insertion/access order, LRU cache
Pick TreeMap when:       sorted keys, range queries needed
Pick ConcurrentHashMap:  multi-threaded environment
Pick Hashtable:          never (legacy, use ConcurrentHashMap)

Pick HashSet when:       fast membership test, no order needed
Pick LinkedHashSet when: deduplicate + preserve insertion order
Pick TreeSet when:       sorted elements, floor/ceiling queries
Pick EnumSet when:       set of enum constants (fastest)
```
