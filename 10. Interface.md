

## 1. What is Interface and How to Define

An **interface** in Java is a reference type that contains abstract method declarations, default methods, static methods, and constants. It's a blueprint that defines a contract for classes to implement.

### Syntax

```java
interface InterfaceName {
    // Abstract method (implicitly public abstract)
    void method1();
    
    // Constant (implicitly public static final)
    int CONSTANT = 100;
    
    // Default method (Java 8+)
    default void defaultMethod() {
        System.out.println("Default implementation");
    }
    
    // Static method (Java 8+)
    static void staticMethod() {
        System.out.println("Static method in interface");
    }
    
    // Private method (Java 9+)
    private void privateHelper() {
        System.out.println("Helper method");
    }
}
```

### Key Points

- Use `interface` keyword to define
- By default, all methods are `public abstract`
- All fields are `public static final` (constants)
- Cannot be instantiated directly
- Supports multiple inheritance

## 2. Why We Need Interface

### Reasons for Using Interfaces

**Abstraction**: Hides implementation details and shows only functionality to the user.

**Multiple Inheritance**: Java doesn't support multiple inheritance with classes, but a class can implement multiple interfaces.

```java
interface Flyable { void fly(); }
interface Swimmable { void swim(); }

class Duck implements Flyable, Swimmable {
    public void fly() { System.out.println("Duck flying"); }
    public void swim() { System.out.println("Duck swimming"); }
}
```

**Loose Coupling**: Reduces dependencies between components.

**Contract Definition**: Ensures that implementing classes follow a specific contract.

**Polymorphism**: Allows treating different objects uniformly through interface reference.

```java
List<String> list1 = new ArrayList<>();  // ArrayList implementation
List<String> list2 = new LinkedList<>(); // LinkedList implementation
```

## 3. Methods in Interface

### Types of Methods in Interface

#### a) Abstract Methods (Before Java 8)

```java
interface Vehicle {
    void start();  // implicitly public abstract
    void stop();
}
```

#### b) Default Methods (Java 8+)

Provide default implementation that can be overridden.

```java
interface Vehicle {
    default void horn() {
        System.out.println("Beep beep!");
    }
}

class Car implements Vehicle {
    // Can use default implementation or override
    @Override
    public void horn() {
        System.out.println("Car horn!");
    }
}
```

#### c) Static Methods (Java 8+)

Utility methods that belong to the interface itself.

```java
interface MathOperations {
    static int add(int a, int b) {
        return a + b;
    }
}

// Call: MathOperations.add(5, 3);
```

#### d) Private Methods (Java 9+)

Helper methods for default/static methods to avoid code duplication.

```java
interface Calculator {
    default int addAndPrint(int a, int b) {
        int result = a + b;
        print(result);
        return result;
    }
    
    private void print(int value) {
        System.out.println("Result: " + value);
    }
}
```

## 4. Fields in an Interface

### Characteristics

- All fields are implicitly `public static final` (constants)
- Must be initialized at declaration
- Cannot be changed once assigned

```java
interface Constants {
    int MAX_VALUE = 100;              // public static final
    String APP_NAME = "MyApp";        // public static final
    double PI = 3.14159;              // public static final
}

// Access: Constants.MAX_VALUE
```

### Cannot Have:

- Instance variables
- Non-final fields
- Private fields (except private methods in Java 9+)

## 5. Interface Implementation

### Single Interface Implementation

```java
interface Printable {
    void print();
}

class Document implements Printable {
    @Override
    public void print() {
        System.out.println("Printing document...");
    }
}
```

### Multiple Interface Implementation

```java
interface Readable {
    void read();
}

interface Writable {
    void write();
}

class File implements Readable, Writable {
    @Override
    public void read() {
        System.out.println("Reading file...");
    }
    
    @Override
    public void write() {
        System.out.println("Writing to file...");
    }
}
```

### Rules

- Use `implements` keyword
- Must override all abstract methods (or declare class as abstract)
- Method signature must match exactly
- Access modifier must be `public` or more accessible

## 6. Nested Interface

An interface declared within another interface or class.

### Interface inside Interface

```java
interface OuterInterface {
    void outerMethod();
    
    interface InnerInterface {
        void innerMethod();
    }
}

class MyClass implements OuterInterface.InnerInterface {
    @Override
    public void innerMethod() {
        System.out.println("Inner method implementation");
    }
}
```

### Interface inside Class

```java
class OuterClass {
    interface InnerInterface {
        void display();
    }
}

class Implementation implements OuterClass.InnerInterface {
    @Override
    public void display() {
        System.out.println("Display from inner interface");
    }
}
```

## 7. Difference between Interface and Abstract Class

|Feature|Interface|Abstract Class|
|---|---|---|
|**Keyword**|`interface`|`abstract class`|
|**Multiple Inheritance**|A class can implement multiple interfaces|A class can extend only one abstract class|
|**Methods**|All methods abstract by default (before Java 8)|Can have both abstract and concrete methods|
|**Variables**|Only `public static final` (constants)|Can have instance variables, any access modifier|
|**Constructor**|Cannot have constructors|Can have constructors|
|**Access Modifiers**|Methods are public by default|Methods can have any access modifier|
|**Default Methods**|Supported from Java 8|Not applicable|
|**When to Use**|Define a contract (what to do)|Share common code among related classes (how to do)|
|**Performance**|Slightly slower (requires extra indirection)|Faster|
|**Implementation**|`implements` keyword|`extends` keyword|

### Example Comparison

```java
// Interface - defines contract
interface Flyable {
    void fly();
}

// Abstract Class - provides partial implementation
abstract class Bird {
    String name;
    
    Bird(String name) {
        this.name = name;
    }
    
    abstract void fly();
    
    void eat() {  // concrete method
        System.out.println(name + " is eating");
    }
}
```

## 8. Java 8 Interface Features

### a) Default Methods

Allows adding new methods to interfaces without breaking existing implementations.

```java
interface Vehicle {
    void start();
    
    default void cleanVehicle() {
        System.out.println("Cleaning vehicle...");
    }
}

class Car implements Vehicle {
    @Override
    public void start() {
        System.out.println("Car starting...");
    }
    // cleanVehicle() inherited, can be overridden if needed
}
```

### b) Static Methods

Utility methods that don't require an instance.

```java
interface StringUtils {
    static boolean isEmpty(String str) {
        return str == null || str.trim().isEmpty();
    }
}

// Usage: StringUtils.isEmpty("test");
```

### c) Functional Interface and Lambda Expression

Interface with exactly one abstract method (SAM - Single Abstract Method).

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
    
    // Can have default and static methods
    default void print(int result) {
        System.out.println("Result: " + result);
    }
}

// Lambda expression usage
Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

System.out.println(add.calculate(5, 3));      // 8
System.out.println(multiply.calculate(5, 3)); // 15
```

**Common Functional Interfaces:**

- `Predicate<T>` - takes argument, returns boolean
- `Function<T,R>` - takes argument, returns result
- `Consumer<T>` - takes argument, returns nothing
- `Supplier<T>` - takes nothing, returns result

## 9. Java 9 Interface Feature

### Private Methods and Private Static Methods

Allows code reuse within interfaces without exposing helper methods.

```java
interface Logger {
    default void logInfo(String message) {
        log(message, "INFO");
    }
    
    default void logError(String message) {
        log(message, "ERROR");
    }
    
    // Private helper method
    private void log(String message, String level) {
        System.out.println(getTimestamp() + " [" + level + "] " + message);
    }
    
    // Private static helper method
    private static String getTimestamp() {
        return java.time.LocalDateTime.now().toString();
    }
}
```

### Benefits

- Code reusability within interface
- Better encapsulation
- Cleaner default method implementations

## Interview Quick Tips

### Common Interview Questions

**Q: Can we create an object of an interface?** A: No, but we can create a reference variable of interface type pointing to an object of implementing class.

**Q: Can interface have constructors?** A: No, interfaces cannot have constructors.

**Q: What happens if a class implements two interfaces with same default method?** A: Compilation error - the class must override the method to resolve ambiguity.

**Q: Difference between marker interface and functional interface?** A: Marker interface has no methods (e.g., Serializable), Functional interface has exactly one abstract method.

**Q: Can we declare interface methods as final or static?** A: Abstract methods cannot be final. Static methods are allowed from Java 8.

### Best Practices

- Use interfaces to define contracts and APIs
- Prefer interfaces over abstract classes for multiple inheritance
- Use functional interfaces with lambdas for cleaner code
- Keep interfaces focused and cohesive (Interface Segregation Principle)
- Use default methods cautiously to maintain backward compatibility

## Code Examples Summary

```java
// Complete example demonstrating all concepts
@FunctionalInterface
interface Payment {
    // Abstract method
    void processPayment(double amount);
    
    // Default method
    default void printReceipt(double amount) {
        System.out.println("Payment of $" + amount + " processed");
        logTransaction(amount);
    }
    
    // Static method
    static boolean isValidAmount(double amount) {
        return amount > 0;
    }
    
    // Private helper (Java 9+)
    private void logTransaction(double amount) {
        System.out.println("Transaction logged: $" + amount);
    }
    
    // Constant
    double MAX_AMOUNT = 10000.0;
}

class CreditCardPayment implements Payment {
    @Override
    public void processPayment(double amount) {
        if (Payment.isValidAmount(amount)) {
            System.out.println("Processing credit card payment: $" + amount);
        }
    }
}

// Usage
Payment payment = new CreditCardPayment();
payment.processPayment(500.0);
payment.printReceipt(500.0);

// Lambda for functional interface
Payment quickPay = (amt) -> System.out.println("Quick pay: $" + amt);
quickPay.processPayment(100.0);
```
