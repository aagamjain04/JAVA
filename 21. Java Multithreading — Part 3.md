## 1. Why `stop()`, `suspend()`, `resume()` are Deprecated ❌

These three methods on the `Thread` class are **deprecated** because they are unsafe.

|Method|What it did|Why deprecated|
|---|---|---|
|`stop()`|Terminates the thread **abruptly**|No lock release, no resource clean-up happens → leaves shared data in inconsistent state|
|`suspend()`|Puts the thread on hold temporarily|**No lock is released** → if another thread needs the same lock, it waits forever → **deadlock**|
|`resume()`|Resumes a suspended thread|Useless and dangerous without `suspend()` — both together can cause deadlock|

> ⚠️ Both `suspend()` + `resume()` together can lead to **deadlock**.

### Deadlock scenario with suspend/resume:

```
Thread T1 → acquires Lock R1
Thread T2 → waiting for Lock R1
T1 gets suspended (lock NOT released) → T2 waits forever → DEADLOCK
```

### Safe alternatives:

```java
// Instead of stop() — use a volatile flag
class MyTask implements Runnable {
    private volatile boolean running = true;

    public void stop() {
        running = false;  // signal the thread to stop
    }

    @Override
    public void run() {
        while (running) {
            // do work
        }
        // cleanup happens naturally here
    }
}

// Instead of suspend()/resume() — use wait()/notify()
synchronized (lock) {
    while (suspended) {
        lock.wait();   // releases the lock while waiting
    }
}
// to resume:
synchronized (lock) {
    suspended = false;
    lock.notifyAll();
}
```

## 2. Thread Joining — `join()`

`join()` makes the **calling thread wait** until the thread on which `join()` is called **finishes execution**.

### Key points:

- Calling `t1.join()` in the main thread → main thread goes to **Timed Waiting** state until `t1` finishes.
- Does **NOT release** monitor lock (it's Timed Waiting, not Waiting).
- Can pass a timeout: `t1.join(2000)` → wait at most 2 seconds.

### Sequence diagram (without join):

```
Main      T1           T2
 |        |             |
 |─start─→| (running)   |
 |─start─────────────→  | (running)
 | (continues immediately)
 |
Main doesn't wait for T1 or T2 → output order is unpredictable
```

### Sequence diagram (with join):

```
Main      T1           T2
 |        |             |
 |─start─→| (running)   |
 |─t1.join()            |
 | (waiting...)         |
 |        |─finishes    |
 |←────────             |
 |─start─────────────→  |
 |─t2.join()
 | (waiting...)
 |                      |─finishes
 |←─────────────────────
 | (continues)
```

### Code Example — Without join:

```java
public class ThreadJoinExample {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println("T1: " + i);
                try { Thread.sleep(500); } catch (InterruptedException e) {}
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println("T2: " + i);
                try { Thread.sleep(500); } catch (InterruptedException e) {}
            }
        });

        t1.start();
        t2.start();
        System.out.println("Main finished");
        // Output: unpredictable interleaving of T1, T2, and Main
    }
}
```

### Code Example — With join:

```java
public class ThreadJoinExample {
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println("T1: " + i);
                try { Thread.sleep(500); } catch (InterruptedException e) {}
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println("T2: " + i);
                try { Thread.sleep(500); } catch (InterruptedException e) {}
            }
        });

        t1.start();
        t1.join();   // main waits for T1 to finish completely

        t2.start();
        t2.join();   // main waits for T2 to finish completely

        System.out.println("Main finished");
        // Output: T1 prints 1-5, then T2 prints 1-5, then "Main finished" — guaranteed order
    }
}
```

### With timeout:

```java
t1.start();
t1.join(2000);  // main waits at most 2 seconds for T1
// continues regardless of whether T1 finished
```

### join() with the suspend/resume deadlock scenario:

```
If T1 acquired Lock R1 and then gets suspended:
  - T2 waiting for Lock R1 → blocked forever
  - No one can call resume() on T1 since T2 is blocked
  - DEADLOCK

join() is safe because it uses wait() internally and releases the monitor lock
```

## 3. Thread Priority

- Each thread has a **priority** value — an integer from **1 (MIN)** to **10 (MAX)**.
- Default priority is **5 (NORM)**.
- Higher priority threads are **preferred** by the thread scheduler, but it is **not guaranteed**.
- Priority is a **hint** to the scheduler — actual behaviour depends on the OS.

### Priority Constants:

```java
Thread.MIN_PRIORITY   // = 1
Thread.NORM_PRIORITY  // = 5 (default)
Thread.MAX_PRIORITY   // = 10
```

### Getting and Setting Priority:

```java
Thread t1 = new Thread(() -> System.out.println("T1 running"));

// Get priority
System.out.println(t1.getPriority());   // 5 (default)

// Set custom priority using setPriority(int priority)
t1.setPriority(10);  // MAX priority
// or
t1.setPriority(Thread.MAX_PRIORITY);

t1.start();
```

### Full example — comparing priorities:

```java
public class ThreadPriorityExample {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 5; i++)
                System.out.println("Low priority T1: " + i);
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 5; i++)
                System.out.println("High priority T2: " + i);
        });

        t1.setPriority(Thread.MIN_PRIORITY);   // 1
        t2.setPriority(Thread.MAX_PRIORITY);   // 10

        t1.start();
        t2.start();
        // T2 is likely (but not guaranteed) to run more often / first
    }
}
```

> ⚠️ **Never rely solely on thread priority** for correctness — use proper synchronization instead.

## 4. Daemon Thread

A **Daemon thread** is a background/service thread that runs **asynchronously** to support other threads. It is automatically killed by the JVM when all **non-daemon (user) threads** finish.

### Key characteristics:

- Runs in the **background** (ASYNC).
- **Does not prevent JVM from shutting down** — JVM exits when only daemon threads remain.
- Examples: Garbage Collector, JIT compiler thread.
- Set before calling `start()`.

### Setting a thread as Daemon:

```java
Thread t1 = new Thread(() -> {
    while (true) {
        System.out.println("Daemon thread running...");
        try { Thread.sleep(500); } catch (InterruptedException e) {}
    }
});

t1.setDaemon(true);   // must call BEFORE start()
t1.start();

System.out.println("Main thread ending...");
// When main ends, JVM shuts down → daemon thread is also killed automatically
```

### Checking if a thread is daemon:

```java
System.out.println(t1.isDaemon());  // true
```

### User Thread vs Daemon Thread:

||User Thread|Daemon Thread|
|---|---|---|
|**Purpose**|Main application work|Background service tasks|
|**JVM shutdown**|JVM waits for all user threads to finish|JVM does NOT wait — kills daemon threads on exit|
|**Examples**|`main` thread, business logic threads|Garbage Collector, Log flusher, Heartbeat|
|**Default**|Yes (default)|No — must call `setDaemon(true)`|
|**Set via**|(default)|`thread.setDaemon(true)` before `start()`|

### Example showing Daemon behaviour:

```java
public class DaemonExample {
    public static void main(String[] args) throws InterruptedException {
        Thread daemonThread = new Thread(() -> {
            int i = 0;
            while (true) {
                System.out.println("Daemon: " + i++);
                try { Thread.sleep(200); } catch (InterruptedException e) {}
            }
        });

        daemonThread.setDaemon(true);
        daemonThread.start();

        // Main thread sleeps 1 second then finishes
        Thread.sleep(1000);
        System.out.println("Main thread done");
        // After this line, JVM exits and daemon thread is killed
        // Daemon won't run infinitely even though its loop is "while(true)"
    }
}
```

> ❗ **Important:** `setDaemon(true)` must be called **before** `start()`. Calling it after throws `IllegalThreadStateException`.

## 5. Quick Reference — Thread Methods

|Method|Description|
|---|---|
|`thread.start()`|Creates new thread and calls `run()` in it|
|`thread.join()`|Calling thread waits until this thread finishes|
|`thread.join(ms)`|Wait at most `ms` milliseconds|
|`Thread.sleep(ms)`|Pauses current thread for ms milliseconds (Timed Waiting)|
|`thread.setPriority(n)`|Set priority 1–10|
|`thread.getPriority()`|Get current priority|
|`thread.setDaemon(true)`|Mark as daemon (before start)|
|`thread.isDaemon()`|Check if daemon|
|`Thread.currentThread()`|Returns reference to currently executing thread|
|`thread.getName()`|Get thread name|
|`thread.setName("name")`|Set thread name|
|`thread.interrupt()`|Interrupt the thread (sets interrupt flag)|
|`Thread.yield()`|Hint to scheduler to let other threads run|

## 6. Common Interview Questions

**Q1. What is `join()` in Java threads and when would you use it?**

> `join()` makes the calling thread wait until the thread it is called on completes. Use it when you need sequential execution between threads — e.g., main thread must wait for computation threads to finish before aggregating results.

**Q2. Why are `stop()`, `suspend()`, and `resume()` deprecated?**

> `stop()` terminates a thread abruptly without releasing locks or cleaning up resources, leaving shared data in an inconsistent state. `suspend()` puts a thread on hold without releasing its locks — if another thread needs the same lock, it blocks forever → deadlock. `resume()` is meaningless without `suspend()`. Use `volatile` flags and `wait()`/`notify()` instead.

**Q3. What is a Daemon thread? Give examples.**

> A daemon thread is a low-priority background thread that is automatically killed by the JVM when all user threads finish. Examples: Garbage Collector, JIT compiler. Use `setDaemon(true)` before `start()`.

**Q4. What happens if you call `setDaemon(true)` after `start()`?**

> It throws `IllegalThreadStateException`. The daemon status must be set before the thread is started.

**Q5. What is Thread Priority? Is it guaranteed?**

> Thread priority is a hint (1–10) to the OS thread scheduler indicating which threads should be preferred. It is **not guaranteed** — the actual scheduling depends on the OS and JVM implementation. Never rely on it for correctness.

**Q6. What is the difference between `join()` and `sleep()`?**

> `sleep(ms)` pauses the current thread for a fixed time regardless of other threads. `join()` pauses the current thread until a **specific other thread** completes (or a timeout elapses). Both put the thread in Timed Waiting state.

**Q7. Does `join()` release the monitor lock?**

> `join()` internally uses `wait()` which does release the monitor lock. So the calling thread does release locks while waiting for the joined thread to finish.

**Q8. How do you safely stop a thread?**

> Use a `volatile boolean` flag:
> 
> ```java
> private volatile boolean running = true;
> public void stopThread() { running = false; }
> public void run() { while (running) { /* work */ } }
> ```
> 
> `volatile` ensures the flag change is visible to all threads immediately.
