## 1. Process vs Thread

### Process

- An **instance of a program** that is getting executed.
- Has its **own resources** — memory, thread, etc.
- OS allocates these resources when it is created.

**Compilation & Execution flow:**

```
javac Test.java  →  generates bytecode (.class file)
java Test        →  JVM starts a new Process; Test class has public static void main() method
```

**JVM Memory allocation:**

```bash
# Set initial heap size to 256MB
java -Xms256m -Xmx2g MainClassName

# -Xms : sets initial heap size (allocated 256MB above)
# -Xmx : max heap size process can get (allocated 2GB above)
#         if tries to allocate more memory → "OutOfMemoryError"
```

---

### Thread

- Known as a **lightweight process**.
- Smallest sequence of instructions **executed by CPU independently**.
- 1 process can have **multiple threads**.
- When a Process is created, it starts with **1 thread** — that initial thread is known as the **'main' thread**.
- From the main thread, we can create more threads to perform tasks concurrently.

```java
public class MultithreadingLearning {
    public static void main(String[] args) {
        System.out.println("Thread Name: " + Thread.currentThread().getName());
    }
}
// Output: Thread Name: main
```

## 2. Memory Architecture — Process & Threads

```
Physical Memory (Total JVM Heap Memory allocated)
┌──────────────────────┬──────────────────────┐
│       Process1       │       Process2       │
│    (JVM Instance1)   │    (JVM Instance2)   │
│  ┌────────────────┐  │  ┌────────────────┐  │
│  │  Heap Memory   │  │  │  Heap Memory   │  │
│  │ ┌────┐ ┌────┐  │  │  │ ┌────┐ ┌────┐ │  │
│  │ │Code│ │Data│  │  │  │ │Code│ │Data│ │  │
│  │ │Seg │ │Seg │  │  │  │ │Seg │ │Seg │ │  │
│  │ └────┘ └────┘  │  │  │ └────┘ └────┘ │  │
│  │ Register Stack │  │  │ Register Stack │  │
│  │ Counter Counter│  │  │ Counter Counter│  │
│  │  Thread1 Thread2  │  │  Thread1 Thread2  │
│  └────────────────┘  │  └────────────────┘  │
└──────────────────────┴──────────────────────┘
          CPU1                CPU2
        Register            Register
          Cache               Cache
              Main Memory (RAM)
```

> Each **Process** gets its **own JVM instance** with its own heap. Threads within a process **share** the heap.

## 3. Memory Segments — What Each Thread Can Access

### Code Segment

- Contains the compiled **BYTECODE** (i.e. machine code) of the Java Program.
- **Read only.**
- All threads within the same process **share** the same code segment.

### Data Segment

- Contains **GLOBAL and STATIC variables**.
- All threads within the same process share the same data segment.
- Threads can **read and modify** the same data.
- ⚠️ **Synchronization is required** between multiple threads.

### Heap

- Objects created at runtime using the `new` keyword are allocated here.
- **Shared among all threads** of the same process (but NOT WITHIN PROCESS — each process has its own heap pointer in physical memory).
- Threads can read and modify the heap data.
- ⚠️ **Synchronization is required** between multiple threads.

### Stack

- **Each thread has its own STACK.**
- Manages **method calls** and **local variables**.
- Not shared — completely private to each thread.

### Register

- When **JIT (Just-in-Time)** compiler converts Bytecode into native machine code, it uses registers to optimize the generated machine code.
- Also helps in **context switching**.
- **Each thread has its own Register.**

### Counter (Program Counter)

- Also known as **Program Counter**.
- Points to the **instruction which is currently being executed**.
- Increments its counter after successfully executing each instruction.
- **Each thread has its own Counter.**

> 📝 **Stack, Register, and Counter** are all managed by JVM — each thread gets its own copy of these.

## 4. Memory — Shared vs Private

|Memory Area|Shared or Private?|Notes|
|---|---|---|
|**Code Segment**|Shared (all threads in process)|Read-only|
|**Data Segment**|Shared (all threads in process)|Has global/static vars; needs sync|
|**Heap**|Shared (all threads in process)|`new` objects; needs sync|
|**Stack**|**Private** (per thread)|Method calls, local vars|
|**Register**|**Private** (per thread)|JIT optimization + context switching|
|**Counter (PC)**|**Private** (per thread)|Points to current instruction|

## 5. Definition of Multithreading

- Allows a program to **perform multiple tasks at the same time**.
- Multiple threads **share the same resources** (memory space) but still can **perform tasks independently**.

---

## 6. Benefits and Challenges

### ✅ Benefits

- **Improved performance** by task parallelism
- **Responsiveness** — UI stays reactive while background tasks run
- **Resource sharing** — threads share memory, reducing overhead

### ⚠️ Challenges

- **Concurrency issues** like deadlock, data inconsistency, race conditions
- **Synchronization overhead** — locking mechanisms add cost
- **Testing and Debugging is difficult** — non-deterministic behaviour

---

## 7. Multitasking vs Multithreading

||Multitasking|Multithreading|
|---|---|---|
|**Unit**|Multiple processes|Multiple threads within one process|
|**Memory**|Each process has its own memory|Threads share the same memory|
|**Overhead**|Higher (process creation is heavy)|Lower (threads are lightweight)|
|**Communication**|Inter-process communication (IPC) needed|Direct — shared memory|
|**Example**|Running browser + music player simultaneously|Browser using multiple threads for rendering, networking, JS|

## 9. Common Interview Questions

**Q1. What is the difference between a Process and a Thread?**

> A Process is an independent program instance with its own memory space. A Thread is a lightweight unit of execution within a process. Threads share the process's memory; processes do not share memory with each other.

**Q2. What memory areas does a Thread have exclusively?**

> Each thread has its own **Stack**, **Register**, and **Program Counter (Counter)**. The Code Segment, Data Segment, and Heap are shared among all threads of the same process.

**Q3. Why is synchronization required in multithreading?**

> Because multiple threads share the **Heap** and **Data Segment**, concurrent read/write operations can cause data inconsistency and race conditions. Synchronization ensures only one thread accesses the critical section at a time.

**Q4. What is context switching?**

> Context switching is when the CPU switches from executing one thread to another. The CPU saves the state of the current thread (registers, program counter) and loads the state of the next thread. Each thread's private Register helps facilitate this.

**Q5. What is the 'main' thread in Java?**

> When a JVM process starts, it creates one thread automatically — the **main thread** — which executes the `public static void main(String[] args)` method. All other threads are created from the main thread.

**Q6. What is JIT and what role do Registers play?**

> JIT (Just-In-Time) compiler converts Java bytecode to native machine code at runtime for performance. Registers are used to optimize this generated machine code and also store thread state during context switching. Each thread has its own set of registers.

**Q7. What happens if a process tries to allocate more memory than `-Xmx`?**

> The JVM throws an `OutOfMemoryError`.

**Q8. What are the challenges of multithreading?**

> Concurrency bugs like **deadlock** (two threads waiting on each other), **race conditions** (unpredictable results from unsynchronized shared access), **synchronization overhead**, and difficulty in **testing/debugging** due to non-deterministic thread scheduling.
