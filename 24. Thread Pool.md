
# Java Thread Pools & ThreadPoolExecutor — Interview Notes 🏊

### Topics: ThreadPool · Executor Hierarchy · ThreadPoolExecutor params · RejectedExecutionHandler

---

## 1. What is a Thread Pool?

- A **collection of threads (workers)** available to perform submitted tasks.
- Once a task is completed, the worker thread **returns to the pool** and waits for a new task.
- **Threads can be reused** — no need to create/destroy threads per task.

```
Application submitting         Task Queue              Thread Pool
    New Tasks         →  [Task n][Task3][Task2][Task1] →  Thread1
                                                          Thread2
                                                          ...
                                                          Thread n
```

---

## 2. Advantages of Thread Pool

|Benefit|Explanation|
|---|---|
|**Thread creation time saved**|Creating a thread allocates stack, heap, program counter etc. — costly. Thread pool reuses threads, avoiding repeated creation.|
|**Thread lifecycle management removed**|Managing Running/Waiting/Terminated states is complex. Thread pool abstracts this away.|
|**Increased performance**|More threads = more context switching. Controlling thread count reduces excess context switching overhead.|

## 4. `ThreadPoolExecutor` — Full Constructor

```java
public ThreadPoolExecutor(
    int corePoolSize,
    int maximumPoolSize,
    long keepAliveTime,
    TimeUnit unit,
    BlockingQueue<Runnable> workQueue,
    ThreadFactory threadFactory,
    RejectedExecutionHandler handler
)
```

### Parameter Details:

#### `corePoolSize`

- Number of threads **initially created** and kept in the pool, **even if idle**.
- These threads are always alive (unless `allowCoreThreadTimeOut` is set to true).

#### `allowCoreThreadTimeOut`

- By default `FALSE` → idle core threads stay alive indefinitely.
- If set to `TRUE` → idle core threads are also terminated after `keepAliveTime`.

#### `keepAliveTime`

- Idle **non-core** (excess) threads are terminated after this time.

#### `maximumPoolSize`

- **Maximum** number of threads allowed in the pool.
- New threads are created beyond `corePoolSize` only when:
    1. Thread count == `corePoolSize` AND
    2. Work queue is also **full**
- New threads created until count < `maximumPoolSize`.
- Excess threads are terminated after `keepAliveTime` of idleness (if pool not shut down or `allowCoreThreadTimeOut` is true).

#### `TimeUnit`

- Unit for `keepAliveTime`: `TimeUnit.MILLISECONDS`, `TimeUnit.SECONDS`, `TimeUnit.HOURS`, etc.

#### `BlockingQueue` (workQueue)

- Queue used to **hold tasks** before worker threads pick them up.
- **Bounded Queue** — fixed capacity → e.g., `ArrayBlockingQueue`
- **Unbounded Queue** — no fixed capacity → e.g., `LinkedBlockingQueue`

> ⚠️ With unbounded queue, `maximumPoolSize` has no effect — new threads beyond `corePoolSize` are never created because the queue never fills up.

#### `ThreadFactory`

- Factory for creating new threads. Use to:
    - Give custom **thread names**
    - Set custom **thread priority**
    - Set **daemon flag**

#### `RejectedExecutionHandler`

- Handler for tasks that **cannot be accepted** by the thread pool (pool is full + queue is full).
- 4 built-in policies:

|Policy|Behaviour|
|---|---|
|`AbortPolicy`|Throws `RejectedExecutionException` (default)|
|`CallerRunsPolicy`|Executes the rejected task in the **caller's thread**|
|`DiscardPolicy`|**Silently discards** the rejected task, no exception|
|`DiscardOldestPolicy`|Discards the **oldest task** in the queue to accommodate the new one|

## 5. Thread Pool Flow Logic

```
New task submitted
       │
       ▼
 Threads < corePoolSize? ──YES──→ Create new thread, run task
       │NO
       ▼
 Queue not full? ──YES──→ Add task to queue, wait for thread
       │NO
       ▼
 Threads < maxPoolSize? ──YES──→ Create new thread, run task
       │NO
       ▼
 RejectedExecutionHandler (AbortPolicy / CallerRunsPolicy / etc.)
```

## 6. Full Example

```java
public class Main {
    public static void main(String[] args) {
        ThreadPoolExecutor poolExecutor = new ThreadPoolExecutor(
            corePoolSize: 2,
            maximumPoolSize: 5,
            keepAliveTime: 1,
            TimeUnit.HOURS,
            new ArrayBlockingQueue<>(capacity: 10),
            new CustomThreadFactory(),
            new CustomRejectedHandler()
        );

        poolExecutor.allowCoreThreadTimeOut(value: true);

        // Submit 25 tasks
        for (int i = 0; i < 25; i++) {
            poolExecutor.submit(() -> {
                try {
                    Thread.sleep(5000);
                    System.out.println("Thread name: " + Thread.currentThread().getName());
                } catch (Exception e) {}
            });
        }

        poolExecutor.shutdown();  // gracefully shuts down after pending tasks complete
    }
}

// Custom RejectedExecutionHandler
class CustomRejectedHandler implements RejectedExecutionHandler {
    @Override
    public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
        // logging
        System.out.println("Task denied: " + r.toString());
    }
}

// Custom ThreadFactory
class CustomThreadFactory implements ThreadFactory {
    @Override
    public Thread newThread(Runnable r) {
        Thread th = new Thread(r);
        return th;
        // here you can set: th.setName(...), th.setPriority(...), th.setDaemon(...)
    }
}
```

## 7. Executors Factory Methods (Shortcut Thread Pools)

```java
// Fixed pool — fixed number of threads
ExecutorService fixed = Executors.newFixedThreadPool(4);

// Single thread pool — 1 thread, tasks queued
ExecutorService single = Executors.newSingleThreadExecutor();

// Cached pool — creates threads as needed, reuses idle ones (max = Integer.MAX_VALUE)
ExecutorService cached = Executors.newCachedThreadPool();

// Scheduled pool — run tasks after delay or periodically
ScheduledExecutorService scheduled = Executors.newScheduledThreadPool(2);
scheduled.schedule(() -> System.out.println("delayed"), 5, TimeUnit.SECONDS);
scheduled.scheduleAtFixedRate(() -> System.out.println("periodic"), 0, 1, TimeUnit.SECONDS);
```

> ⚠️ Prefer `ThreadPoolExecutor` over `Executors` factory methods in production — factories hide important parameters (like unbounded queues in `newFixedThreadPool`) that can cause `OutOfMemoryError`.

## 8. How to Determine Thread Pool Size

**Interview Question:** _Why corePoolSize = 2? Why not 10 or 15?_

The thread pool min and max size depends on:

- **CPU Cores** — number of available processor cores
- **JVM Memory** — each thread consumes stack memory
- **Task Nature** — CPU Intensive vs I/O Intensive
- **Concurrency Requirement** — high / medium / low
- **Memory required** to process a request
- **Throughput** targets

It's an **iterative process** — set initial values and update based on monitoring.

### Formula:

```
Max No. of Threads = No. of CPU Cores × (1 + Request Waiting Time / Processing Time)
```

**Example:**

```
CPU Cores = 4
Request waiting time = 10ms
Processing time = 100ms

Max Threads = 4 × (1 + 10/100) = 4 × 1.1 = 4.4 ≈ 4 threads
```

> ⚠️ This formula doesn't account for **Memory** — always verify with load testing and monitoring.

## 9. Common Interview Questions

**Q1. What is a Thread Pool and why use it?**

> A thread pool is a collection of pre-created, reusable worker threads. Benefits: avoids thread creation overhead, abstracts lifecycle management, reduces excessive context switching.

**Q2. What is the difference between `corePoolSize` and `maximumPoolSize`?**

> `corePoolSize` is the number of threads always kept alive (even idle). `maximumPoolSize` is the ceiling — extra threads beyond core are created only when core threads are busy AND the queue is full. These extra threads are terminated after `keepAliveTime` of idleness.

**Q3. When does a task get rejected?**

> When the thread count has reached `maximumPoolSize` AND the work queue is also full. The `RejectedExecutionHandler` is then invoked.

**Q4. What are the 4 RejectedExecutionHandler policies?**

> `AbortPolicy` (throws exception), `CallerRunsPolicy` (caller thread runs the task), `DiscardPolicy` (silently drops it), `DiscardOldestPolicy` (drops oldest queued task to make room).

**Q5. What is the difference between bounded and unbounded queues in thread pools?**

> Bounded queue (e.g., `ArrayBlockingQueue`) has fixed capacity — when full, new threads up to `maximumPoolSize`are created. Unbounded queue (e.g., `LinkedBlockingQueue`) never fills — `maximumPoolSize` has no effect and tasks just pile up, risking `OutOfMemoryError`.

**Q6. Why should you prefer `ThreadPoolExecutor` over `Executors.newFixedThreadPool()`?**

> `newFixedThreadPool` uses an **unbounded** `LinkedBlockingQueue` internally — tasks queue up without bound, potentially causing `OutOfMemoryError` under heavy load. `ThreadPoolExecutor` makes all parameters explicit, giving you full control.

**Q7. What does `shutdown()` vs `shutdownNow()` do?**

> `shutdown()` — stops accepting new tasks, waits for already-submitted tasks to complete (graceful). `shutdownNow()` — attempts to stop all actively executing tasks, halts queued tasks, returns the list of queued-but-unstarted tasks.
