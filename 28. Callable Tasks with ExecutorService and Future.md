

# Java Callable, Future & ExecutorService

## Asynchronous Task Execution with Thread Pools

---

## 🎯 The Problem `Runnable` Can't Solve

`Runnable` is fine for fire-and-forget tasks, but falls short when you need:

- A **return value** from the task (e.g., a computed sum, a fetched price)
- **Checked exception handling** inside the task

That's where `Callable` + `Future` come in.

|Feature|`Runnable`|`Callable`|
|---|---|---|
|Returns a result|❌ `void`|✅ Generic type `T`|
|Throws checked exceptions|❌|✅|
|Method to override|`run()`|`call()`|
|Works with ExecutorService|✅|✅|

---

## 🔑 Core Components

### 1. `Callable<T>` — The Task

A functional interface in `java.util.concurrent` representing a unit of work that **returns a result**.

```java
class StockPriceFetcher implements Callable<Double> {
    private String stockSymbol;

    public StockPriceFetcher(String stockSymbol) {
        this.stockSymbol = stockSymbol;
    }

    @Override
    public Double call() throws Exception {
        Thread.sleep(5000);           // simulate slow API call
        return Math.random() * 1000;  // return a result
    }
}
```

Key points:

- The generic type `<Double>` declares what `call()` will return
- Override `call()` instead of `run()`
- Can `throw Exception` — unlike `Runnable`

---

### 2. `Future<T>` — The Promise

When you submit a `Callable` to an executor, you get back a `Future` — a **placeholder for a result that isn't ready yet**.

```java
Future<Double> future = executor.submit(task);
```

**Important `Future` methods:**

|Method|Blocking?|Purpose|
|---|---|---|
|`get()`|✅ Yes — waits until done|Retrieve the result|
|`isDone()`|❌ No — returns immediately|Check if task has completed|
|`cancel()`|❌ No|Cancel a pending task|

> ⚠️ Calling `get()` without checking `isDone()` first will **block your main thread** until the result is ready — this can make your app appear frozen.

---

### 3. `ExecutorService` — The Thread Pool Manager

Manages a pool of reusable threads. You submit tasks; it assigns them to available threads.

```java
ExecutorService executor = Executors.newFixedThreadPool(2); // pool of 2 threads
Future<Double> future = executor.submit(task);              // returns Future immediately
executor.shutdown();                                         // no new tasks, finish existing
```

`submit()` returns a `Future` **immediately** — the task runs in the background while your main thread continues.

## 🏗️ Full Example — Async Stock Price Fetcher

Simulates fetching prices for 5 stocks concurrently using only 2 threads.

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

class StockPriceFetcher implements Callable<Double> {
    private String stockSymbol;

    public StockPriceFetcher(String stockSymbol) {
        this.stockSymbol = stockSymbol;
    }

    @Override
    public Double call() throws Exception {
        Thread.sleep(5000);           // simulate API latency
        return Math.random() * 1000;
    }
}

public class Main {
    public static void main(String[] args) throws Exception {

        List<String> stockSymbols = Arrays.asList("AAPL", "GOOGL", "AMZN", "MSFT", "TSLA");
        List<Future<Double>> futures = new ArrayList<>();

        // Step 1: Create thread pool
        ExecutorService executor = Executors.newFixedThreadPool(2);

        // Step 2: Submit all tasks (non-blocking — returns Futures immediately)
        for (String stock : stockSymbols) {
            Future<Double> future = executor.submit(new StockPriceFetcher(stock));
            futures.add(future);
        }

        executor.shutdown(); // stop accepting new tasks; existing tasks still finish

        // Step 3: Safely retrieve results
        for (int i = 0; i < stockSymbols.size(); i++) {
            Future<Double> future = futures.get(i);

            // Poll with isDone() — avoids blocking the main thread
            while (!future.isDone()) {
                System.out.println("waiting...");
                Thread.sleep(2000); // check every 2 seconds
            }

            // get() is non-blocking now since isDone() returned true
            Double price = future.get();
            System.out.println("Price for " + stockSymbols.get(i) + " = " + price);
        }
    }
}
```

```

───────────────                  ───────────────────────
submit AAPL task  ─────────────► Thread-1: running AAPL (5s sleep)
submit GOOGL task ─────────────► Thread-2: running GOOGL (5s sleep)
submit AMZN task  ──► [queued]
submit MSFT task  ──► [queued]
submit TSLA task  ──► [queued]
executor.shutdown()

poll isDone() for AAPL...
  → waiting... (t=2s)
  → waiting... (t=4s)
  → AAPL done! (t=5s) ◄──────── Thread-1 done → picks up AMZN
  → print AAPL price
poll isDone() for GOOGL...
  → GOOGL done! (already done)
  → print GOOGL price
poll isDone() for AMZN...        Thread-2 done → picks up MSFT
  → waiting...
  ...
```

With a pool of 2, **5 tasks take ~15 seconds** total. With a pool of 5, all would finish in **~5 seconds**. Pool size is a tuning decision based on available resources.

## ⚠️ Common Pitfalls

|Mistake|Problem|Fix|
|---|---|---|
|Calling `get()` right after `submit()`|Blocks main thread — defeats concurrency|Submit all tasks first, then retrieve|
|Using `if isDone()` instead of `while`|Race condition — might call `get()` too early|Always use `while (!future.isDone())`|
|Forgetting `executor.shutdown()`|JVM won't exit — threads keep running|Always call `shutdown()` or use try-with-resources|
|Ignoring exceptions from `get()`|`ExecutionException` wraps errors thrown inside `call()`|Wrap `get()` in try-catch for production code|

---

## 🛡️ Production-Safe Result Retrieval

```java
try {
    Double price = future.get();
} catch (ExecutionException e) {
    // exception thrown inside call() is wrapped here
    System.err.println("Task failed: " + e.getCause());
} catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // restore interrupted status
}
```

## 🧠 Mental Model — The Restaurant Kitchen

|Concept|Analogy|
|---|---|
|`Callable` task|A food order placed|
|`ExecutorService`|The kitchen with N chefs|
|`Future`|The ticket/buzzer you get when ordering|
|`isDone()`|Checking if your buzzer is lit|
|`get()`|Walking up and collecting your food|

You don't stand at the counter blocking everyone — you take your ticket, sit down, and check periodically. That's exactly what `isDone()` + `get()` does.

## 🔗 `ExecutorService` Types — Quick Reference

```java
Executors.newFixedThreadPool(n)      // fixed n threads — best for known workloads
Executors.newCachedThreadPool()      // grows/shrinks dynamically — good for short tasks
Executors.newSingleThreadExecutor()  // 1 thread — tasks run sequentially
Executors.newScheduledThreadPool(n)  // for delayed / periodic tasks
```
