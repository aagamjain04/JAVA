

### Topics: ReentrantLock · ReadWriteLock · StampedLock · Semaphore · Condition

---

## Overview — `synchronized` vs Lock API

|Feature|`synchronized`|Lock API (`java.util.concurrent.locks`)|
|---|---|---|
|Lock acquisition|Automatic (block entry/exit)|Manual (`lock()` / `unlock()`)|
|Try to acquire|Not supported|`tryLock()` supported|
|Interruptible|Not supported|`lockInterruptibly()` supported|
|Fairness|Not configurable|Configurable (fair/unfair)|
|Multiple conditions|One (via `wait`/`notify`)|Multiple `Condition` objects|
|Read/Write separation|No|Yes (ReadWriteLock)|

> ⚠️ Always call `unlock()` in a **`finally`** block to guarantee release even on exception.

## 1. ReentrantLock

- A **reentrant** mutual exclusion lock — the same thread can acquire it multiple times without deadlocking itself.
- More flexible than `synchronized` — explicit lock/unlock.
- Supports **fairness** mode: `new ReentrantLock(true)` → longest-waiting thread gets lock first.

### Key Methods:

```
lock.lock()           – acquire the lock (blocks if unavailable)
lock.unlock()         – release the lock
lock.tryLock()        – try to acquire, returns true/false immediately
lock.tryLock(n, unit) – try to acquire within timeout
lock.isLocked()       – check if locked
lock.isHeldByCurrentThread() – check if current thread holds it
```

### Code Example:

```java
public class SharedResource {
    boolean isAvailable = false;
    ReentrantLock lock = new ReentrantLock();

    public void producer() {
        try {
            lock.lock();
            System.out.println("Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = true;
            Thread.sleep(4000);
        } catch (Exception e) {
            // handle
        } finally {
            lock.unlock();  // always unlock in finally!
            System.out.println("Lock release by: " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        Thread th1 = new Thread(() -> resource.producer());
        Thread th2 = new Thread(() -> resource.producer());

        th1.start();
        th2.start();
        // th1 acquires lock first → th2 waits → th1 releases → th2 acquires
    }
}
```

### Reentrant behaviour:

```java
ReentrantLock lock = new ReentrantLock();

lock.lock();       // count = 1
lock.lock();       // count = 2  (same thread — no deadlock)
lock.unlock();     // count = 1
lock.unlock();     // count = 0  (fully released)
```

## 2. ReadWriteLock (`ReentrantReadWriteLock`)

- **ReadLock:** More than **1 thread** can acquire the read lock simultaneously (concurrent reads are safe).
- **WriteLock:** Only **1 thread** can acquire the write lock (exclusive — blocks all readers and writers).

> Use when reads are much more frequent than writes (e.g., caches, configurations).

### Key concept:

```
Multiple threads reading    → ALL can hold ReadLock simultaneously ✅
One thread writing          → exclusive WriteLock, no readers allowed ✅
Reader + Writer at same time → Writer must wait for all readers to finish ✅
```

### Code Example:

```java
public class SharedResource {
    boolean isAvailable = false;

    public void producer(ReadWriteLock lock) {
        try {
            lock.readLock().lock();
            System.out.println("Read Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = true;
            Thread.sleep(4000);
        } catch (Exception e) {
            // handle
        } finally {
            lock.readLock().unlock();
            System.out.println("Read Lock release by: " + Thread.currentThread().getName());
        }
    }

    public void consume(ReadWriteLock lock) {
        try {
            lock.writeLock().lock();
            System.out.println("Write Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = false;
        } catch (Exception e) {
            // handle
        } finally {
            lock.writeLock().unlock();
            System.out.println("Write Lock release by: " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();
        ReadWriteLock lock = new ReentrantReadWriteLock();

        // Two readers — can run concurrently
        Thread th1 = new Thread(() -> resource.producer(lock));
        Thread th2 = new Thread(() -> resource.producer(lock));

        // One writer on a different resource instance
        SharedResource resource1 = new SharedResource();
        Thread th3 = new Thread(() -> resource1.consume(lock));

        th1.start();
        th2.start();
        th3.start();
    }
}
```

## 3. StampedLock

A **StampedLock** has two capabilities:

### Capability 1 — Read/Write Lock (like ReadWriteLock)

Returns a **stamp** (long) when lock is acquired; the same stamp is used to unlock.

```java
public class SharedResource {
    boolean isAvailable = false;
    StampedLock lock = new StampedLock();

    // Read lock (like ReadWriteLock)
    public void producer() {
        long stamp = lock.readLock();
        try {
            System.out.println("Read Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = true;
            Thread.sleep(6000);
        } catch (Exception e) {
            // handle
        } finally {
            lock.unlockRead(stamp);   // use stamp to unlock
            System.out.println("Read Lock release by: " + Thread.currentThread().getName());
        }
    }

    // Write lock
    public void consume() {
        long stamp = lock.writeLock();
        try {
            System.out.println("Write Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = false;
        } catch (Exception e) {
            // handle
        } finally {
            lock.unlockWrite(stamp);   // use stamp to unlock
            System.out.println("Write Lock release by: " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        Thread th1 = new Thread(() -> resource.producer());
        Thread th2 = new Thread(() -> resource.producer());
        Thread th3 = new Thread(() -> resource.consume());

        th1.start();
        th2.start();
        th3.start();
    }
}
```

### Capability 2 — Optimistic Lock (unique to StampedLock)

An **optimistic read** does NOT actually acquire the lock — it just gets a stamp and validates later. If another thread wrote during the optimistic read, the stamp becomes invalid → roll back.

> Use when reads are very frequent and conflicts are rare — much faster than a full read lock.

```java
public class SharedResource {
    int a = 10;
    StampedLock lock = new StampedLock();

    public void producer() {
        long stamp = lock.tryOptimisticRead();  // no lock acquired!
        try {
            System.out.println("Taken optimistic lock");
            a = 11;
            Thread.sleep(4000);

            if (lock.validate(stamp)) {
                // stamp is still valid → no writer interfered
                System.out.println("Updated a value successfully");
            } else {
                // stamp invalid → a writer changed data → rollback
                System.out.println("rollback of work");
                a = 10;  // rollback
            }
        } catch (Exception e) {
            // handle
        }
    }

    public void consumer() {
        long stamp = lock.writeLock();
        System.out.println("Write Lock acquired by: " + Thread.currentThread().getName());
        try {
            System.out.println("performing work");
            a = 7;
        } finally {
            lock.unlockWrite(stamp);
            System.out.println("Write Lock released by: " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        Thread th1 = new Thread(() -> resource.producer());
        Thread th2 = new Thread(() -> resource.consumer());

        th1.start();
        th2.start();
    }
}
```

### StampedLock vs ReadWriteLock:

||ReadWriteLock|StampedLock|
|---|---|---|
|Read/Write support|✅|✅|
|Optimistic read|❌|✅|
|Reentrancy|✅ (Reentrant)|❌ (NOT reentrant)|
|Performance|Good|Better for read-heavy|
|Stamp concept|No|Yes — long stamp used to unlock|

## 4. Semaphore

A **Semaphore** controls access by maintaining a count of **permits**. Threads must acquire a permit before proceeding and release it when done.

- `new Semaphore(permits)` — creates semaphore with `permits` number of slots.
- Unlike locks, **any thread** can release (not just the one that acquired).
- Used to **limit concurrent access** to a resource (e.g., connection pool, rate limiting).

```
Semaphore(2) → up to 2 threads can be inside the critical section simultaneously
```

### Key Methods:

```
semaphore.acquire()   – acquire a permit (blocks if none available)
semaphore.release()   – release a permit
semaphore.availablePermits() – check how many permits are free
```

### Code Example:

```java
public class SharedResource {
    boolean isAvailable = false;
    Semaphore lock = new Semaphore(permits: 2);  // 2 threads allowed concurrently

    public void producer() {
        try {
            lock.acquire();
            System.out.println("Lock acquired by: " + Thread.currentThread().getName());
            isAvailable = true;
            Thread.sleep(4000);
        } catch (Exception e) {
            // handle
        } finally {
            lock.release();
            System.out.println("Lock release by: " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        // 4 threads competing for 2 permits
        Thread th1 = new Thread(() -> resource.producer());
        Thread th2 = new Thread(() -> resource.producer());
        Thread th3 = new Thread(() -> resource.producer());
        Thread th4 = new Thread(() -> resource.producer());

        th1.start();
        th2.start();
        th3.start();
        th4.start();
        // At most 2 threads inside at a time; others wait for a permit
    }
}
```

### Semaphore vs ReentrantLock:

||ReentrantLock|Semaphore|
|---|---|---|
|Concurrent access|1 thread|N threads (configurable permits)|
|Owner|Only acquirer can unlock|Any thread can release|
|Use case|Mutual exclusion|Rate limiting, pooling|
|Fairness|Optional|Optional (`new Semaphore(n, true)`)|

## 5. Condition

`Condition` works with `ReentrantLock` and is the Lock API equivalent of `wait()`/`notify()` on `synchronized`.

```
await()  =  wait()     (releases lock, waits)
signal() =  notify()   (wakes one waiting thread)
signalAll() = notifyAll()
```

### How to use:

```java
ReentrantLock lock = new ReentrantLock();
Condition condition = lock.newCondition();  // create condition tied to this lock

// Thread 1 — waits
lock.lock();
try {
    while (!conditionMet) {
        condition.await();   // releases lock and waits
    }
    // do work
} finally {
    lock.unlock();
}

// Thread 2 — signals
lock.lock();
try {
    conditionMet = true;
    condition.signal();   // wakes one waiting thread
} finally {
    lock.unlock();
}
```

### Condition vs wait/notify:

||`wait()` / `notify()`|`Condition.await()` / `signal()`|
|---|---|---|
|Works with|`synchronized`|`ReentrantLock`|
|Multiple conditions|❌ (one per object)|✅ (multiple per lock)|
|Spurious wakeup handling|Manual `while` loop|Same — manual `while` loop|
|Interruptible|Yes|Yes|

### Producer-Consumer with Condition:

```java
class SharedBuffer {
    private final int CAPACITY = 5;
    private final Queue<Integer> buffer = new LinkedList<>();
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull  = lock.newCondition();  // producer waits here
    private final Condition notEmpty = lock.newCondition();  // consumer waits here

    public void produce(int value) throws InterruptedException {
        lock.lock();
        try {
            while (buffer.size() == CAPACITY) {
                notFull.await();  // buffer full → producer waits
            }
            buffer.add(value);
            System.out.println("Produced: " + value);
            notEmpty.signal();  // notify consumer
        } finally {
            lock.unlock();
        }
    }

    public int consume() throws InterruptedException {
        lock.lock();
        try {
            while (buffer.isEmpty()) {
                notEmpty.await();  // buffer empty → consumer waits
            }
            int value = buffer.poll();
            System.out.println("Consumed: " + value);
            notFull.signal();  // notify producer
            return value;
        } finally {
            lock.unlock();
        }
    }
}
```

> ✅ Using **two separate Conditions** (`notFull` + `notEmpty`) is more efficient than `notifyAll()` — wakes only the relevant waiting thread.

## 6. Lock Types — Quick Comparison

|Lock|Concurrent Readers|Exclusive Writer|Optimistic Read|Permits > 1|Reentrancy|
|---|---|---|---|---|---|
|`ReentrantLock`|❌ (1 at a time)|✅|❌|❌|✅|
|`ReadWriteLock`|✅ (many)|✅ (exclusive)|❌|❌|✅|
|`StampedLock`|✅ (many)|✅ (exclusive)|✅|❌|❌|
|`Semaphore`|✅ (N permits)|—|❌|✅|❌|

## 7. Common Interview Questions

**Q1. What is the difference between `synchronized` and `ReentrantLock`?**

> Both provide mutual exclusion but `ReentrantLock` is more flexible: it supports `tryLock()`, timed lock acquisition, interruptible locking, fairness policy, and multiple `Condition` objects. `synchronized` is simpler and automatically releases the lock. Always use `finally` with `ReentrantLock` to guarantee unlock.

**Q2. What is a ReentrantLock and why is it "reentrant"?**

> Reentrant means the same thread can acquire the lock multiple times without deadlocking itself. The lock keeps a hold count — each `lock()` increments it, each `unlock()` decrements it. The lock is only released when the count reaches zero.

**Q3. What is ReadWriteLock and when would you use it?**

> `ReadWriteLock` has two locks: a read lock (shared — multiple threads can hold it simultaneously) and a write lock (exclusive — only one thread can hold it). Use it when reads vastly outnumber writes (e.g., in-memory caches) to improve throughput.

**Q4. What is a StampedLock? How does optimistic locking work?**

> `StampedLock` extends ReadWriteLock with an optimistic read mode. `tryOptimisticRead()` returns a stamp without blocking. After doing the read, call `validate(stamp)` — if it returns `true`, no writer intervened and the read is valid. If `false`, a write occurred and you must retry or fall back to a full read lock.

**Q5. What is a Semaphore? How does it differ from a lock?**

> A Semaphore maintains a count of permits. `acquire()` decrements the count (blocks if 0); `release()` increments it. Unlike a lock, it allows N threads in simultaneously (N = initial permits), and any thread can release (not just the acquirer). Used for rate limiting and connection pools.

**Q6. What is a `Condition` and how does it relate to `wait()`/`notify()`?**

> `Condition` is the Lock API equivalent of `wait()`/`notify()`. `condition.await()` = `wait()` (releases the lock and waits). `condition.signal()` = `notify()`. The advantage: one `ReentrantLock` can have **multiple** `Condition` objects, allowing fine-grained thread signalling (e.g., one condition for "not full", another for "not empty" in a bounded buffer).

**Q7. Why must `unlock()` always be in a `finally` block?**

> If an exception is thrown inside the locked section and `unlock()` is not in `finally`, the lock is never released → all other threads waiting for the lock will block forever (effectively a deadlock).

**Q8. What is the difference between `Semaphore(1)` and `ReentrantLock`?**

> Both allow only 1 thread in at a time, but: `ReentrantLock` is reentrant (same thread can re-acquire), owner-based (only the locker can unlock), and has `Condition` support. `Semaphore(1)` is not reentrant and any thread can release the permit — making it suitable for signalling between threads.
