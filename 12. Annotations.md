

## 1. What is an Annotation?

An annotation is a way of adding **META DATA** to Java code.

- Usage is **optional** — annotations never directly change how code executes
- They can provide extra information **at runtime** and allow additional logic to be injected
- They can be read at runtime using **Reflection** 
- They can be applied to: **Classes, Methods, Interfaces, Fields, Parameters**, etc.

### Simple Example

```java
// Without annotation
public interface Bird {
    public boolean fly();
}

// With annotation — compiler enforces the override contract
public class Eagle implements Bird {
    @Override
    public boolean fly() {
        return true;
    }
}
```

## 3. Pre-Defined Annotations Used on Java Code

### `@Deprecated`

- Marks a method, class, or field as **outdated** — signals it should no longer be used
- Can be used over: **Field, Method, Package, Parameter, Constructor, Local Variable, Module, Annotation Type**
- IDE will show a **strikethrough** on any usage

```java
@Deprecated
public void fly() { ... }
```

---

### `@Override`

- Tells the compiler to **check that the method overrides** a parent method
- Throws a **compile-time error** if signatures don't match the parent
- Can be used over: **Methods only**

```java
public interface Bird {
    public void fly();
}

public class Eagle implements Bird {
    @Override
    public boolean fly() {   // Compile error! Return type doesn't match
        return true;
    }
}
```

> **Interview point:** `@Override` is compile-time safety net — without it you might silently create a new method instead of overriding.

---

### `@SuppressWarnings`

- Tells the compiler to **ignore specific compile warnings**
- Does NOT suppress Runtime exceptions
- Can be used over: **Field, Method, Parameter, Constructor, Local Variable, Type (Class / Interface / Enum)**

```java
@SuppressWarnings("unchecked")
public void someMethod() { ... }
```

**Common warning types:** `unchecked`, `deprecation`, `rawtypes`, `unused`

---

### `@FunctionalInterface`

- Restricts the interface to have **only 1 abstract method**
- Throws a **Compilation error** if more than 1 abstract method is found
- Can be used over: **Type (Class or Interface or Enum)**
- Essential for **lambda expressions** — lambdas implement functional interfaces

```java
@FunctionalInterface
public interface Bird {
    public boolean fly();   // OK — only 1 abstract method
    public void eat();      // Compile error! Second abstract method
}
```

---

### `@SafeVarargs`

- Suppresses "heap pollution warning" when using generics with varargs
- Validly used when the method does not perform unsafe operations on its varargs parameter

## 4. Meta-Annotations (Annotations used ON Annotations)

These are used when **creating custom annotations** to control their behaviour.

---

### `@Target`

- Specifies **where** the annotation can be applied
- Takes an `ElementType` argument

```java
@Target(ElementType.METHOD)
public @interface MyAnnotation { }

@Target({ElementType.TYPE, ElementType.METHOD})  // multiple targets
public @interface MyAnnotation { }
```

**ElementType values:**

|ElementType|Where it applies|
|---|---|
|`TYPE`|Class, Interface, Enum|
|`FIELD`|Fields|
|`METHOD`|Methods|
|`PARAMETER`|Method parameters|
|`CONSTRUCTOR`|Constructors|
|`LOCAL_VARIABLE`|Local variables|
|`ANNOTATION_TYPE`|Other annotations|
|`PACKAGE`|Packages|
|`TYPE_PARAMETER`|Generic type parameters (Java 8+)|
|`TYPE_USE`|Any use of a type (Java 8+)|

---

### `@Retention`

- Specifies **how long** the annotation information is retained

```java
@Retention(RetentionPolicy.RUNTIME)
public @interface MyAnnotation { }
```

**RetentionPolicy values:**

|Policy|Behaviour|
|---|---|
|`SOURCE`|Discarded by compiler — NOT in `.class` file|
|`CLASS`|Recorded in `.class` file but **ignored by JVM** at runtime (default)|
|`RUNTIME`|Available at runtime via Reflection ✅|

> **Interview point:** If you want to read an annotation using Reflection, you **must** use `RetentionPolicy.RUNTIME`.

---

### `@Documented`

- By default, annotations are **not** included in Javadoc
- Adding `@Documented` means your annotation **will appear in generated Javadoc**

---

### `@Inherited`

- If a parent class has this annotation, **subclasses automatically inherit it**
- Works only for **class-level** annotations (not methods or fields)

```java
// Without @Inherited: SubClass does NOT get @MyAnnotation
// With @Inherited:    SubClass automatically gets @MyAnnotation
```

**Outputs differ:**

```
// Without @Inherited
Parent annotation: @MyAnnotation
Child annotation: null

// With @Inherited
Parent annotation: @MyAnnotation
Child annotation: @MyAnnotation    ← inherited
```

---

### `@Repeatable`

- Allows the **same annotation to be applied more than once** to the same element
- Requires a **container annotation** to hold the repeated values

```java
// Step 1: Create the container annotation
@Retention(RetentionPolicy.RUNTIME)
@interface CategoryName {
    String[] value();
}

// Step 2: Mark the annotation as repeatable, referencing the container
@Repeatable(CategoryName.class)
@interface Category {
    String value();
}

// Step 3: Use it multiple times on the same element
@Category("Bird")
@Category("StringThing")
@Category("Carnivore")
public class Eagle {
    public void fly() { }
}
```

**Reading repeatable annotations via Reflection:**

```java
public static void main(String[] args) {
    Category[] categories = Eagle.class.getAnnotationsByType(Category.class);
    for (Category category : categories) {
        System.out.println(category.value());
    }
}
// Output:
// Bird
// StringThing
// Carnivore
```

## 5. User-Defined / Custom Annotations

Custom annotations are created using the `@interface` keyword.

### Creating an Empty Body Annotation

```java
public @interface MyCustomAnnotation { }

// Usage
@MyCustomAnnotation
public class Eagle {
    public void fly() { }
}
```

---

### Creating an Annotation with an Element (like a field)

- No parameters, no body — **return type acts like a field**
- Return type must be: **Primitive, Class, String, enum, annotation, or array of these types**

```java
public @interface MyCustomAnnotation {
    String name();   // element — must be provided on usage
}

// Usage — must supply the value
@MyCustomAnnotation(name = "StringValue")
public class Eagle {
    public void fly() { }
}
```

---

### Creating an Annotation with Default Values

- Use the `default` keyword
- **Default value cannot be null**

```java
public @interface MyCustomAnnotation {
    String name() default "hello";
}

// Usage — value is optional now (defaults to "hello")
@MyCustomAnnotation
public class Eagle {
    public void fly() { }
}
```

---

## 6. Reading Annotations at Runtime via Reflection

For any annotation to be readable at runtime, it must have `@Retention(RetentionPolicy.RUNTIME)`.

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface MyCustomAnnotation {
    String name() default "hello";
}

@MyCustomAnnotation(name = "Eagle class")
public class Eagle { }

// Reading it
public static void main(String[] args) {
    Class eagleClass = Eagle.class;
    MyCustomAnnotation annotation = (MyCustomAnnotation) eagleClass.getAnnotation(MyCustomAnnotation.class);
    System.out.println(annotation.name());  // Eagle class
}
```

---

## 7. Quick-Reference Cheat Sheet

```
Custom Annotation creation steps:
  1. @interface MyAnnotation { }              ← define it
  2. Add @Target(ElementType.X)              ← where it can be used
  3. Add @Retention(RetentionPolicy.RUNTIME) ← needed for Reflection
  4. Add elements with default values        ← optional
  5. Apply: @MyAnnotation(element = "val")   ← use it
  6. Read:  clazz.getAnnotation(MyAnnotation.class) ← reflect on it
```

## 8. Common Interview Questions

**Q: What is an annotation in Java?**

> A form of metadata added to Java code that is optional and does not directly affect execution. It can provide information to the compiler, tools, or at runtime via Reflection.

**Q: What is the difference between `@Retention(SOURCE)`, `CLASS`, and `RUNTIME`?**

> SOURCE is discarded by the compiler. CLASS is stored in the `.class` file but not loaded by the JVM. RUNTIME is available at runtime — required for Reflection-based processing (e.g., Spring, JUnit).

**Q: What is `@FunctionalInterface` used for?**

> It restricts an interface to exactly one abstract method, making it usable as a lambda target. It causes a compile error if you accidentally add a second abstract method.

**Q: What is the difference between `getAnnotation()` and `getAnnotationsByType()`?**

> `getAnnotation()` retrieves a single annotation of a given type. `getAnnotationsByType()` is used for `@Repeatable`annotations — it returns an array of all repeated annotations of that type.

**Q: Why would you use `@SuppressWarnings` and what are its risks?**

> To silence compiler warnings that you've deliberately decided to accept. The risk is masking real bugs — use it sparingly and always with a specific warning type string, never blindly.

**Q: What is a meta-annotation?**

> An annotation that applies to other annotations. The five meta-annotations in Java are `@Target`, `@Retention`, `@Documented`, `@Inherited`, and `@Repeatable`.

**Q: Can annotation elements have any return type?**

> No. Return types are restricted to: primitives (`int`, `boolean`, etc.), `String`, `Class`, `enum`, another annotation type, or an array of any of the above. `null` is not a valid default value.

**Q: What is `@Inherited` and what are its limitations?**

> It allows a class-level annotation to be automatically inherited by subclasses. It does **not** work for method or field annotations, and only applies to class inheritance (not interface implementation).
