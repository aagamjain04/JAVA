
## `printSeqThread` — Printing `1A2B3C...26Z`

---

## 🎯 Goal

Two threads must alternate to produce the output `1A2B3C...26Z`:

|Thread|Responsibility|
|---|---|
|`t1`|Prints numbers `1` to `26`|
|`t2`|Prints letters `A` to `Z`|

The challenge: **enforce strict alternation** between the two threads without using `sleep()` or busy-waiting.

---
`wait()` / `notify()` — Most Fundamental

```java

public class PrintSeq {
    private static int turn = 0; // 0 = number's turn, 1 = char's turn

    public static void main(String[] args) {
        Object lock = new Object();

        Thread t1 = new Thread(() -> {
            for (int i = 1; i <= 26; i++) {
                synchronized (lock) {
                    while (turn != 0) {
                        try { lock.wait(); } catch (InterruptedException e) {}
                    }
                    System.out.print(i);
                    turn = 1;
                    lock.notifyAll();
                }
            }
        });

        Thread t2 = new Thread(() -> {
            for (char ch = 'A'; ch <= 'Z'; ch++) {
                synchronized (lock) {
                    while (turn != 1) {
                        try { lock.wait(); } catch (InterruptedException e) {}
                    }
                    System.out.print(ch);
                    turn = 0;
                    lock.notifyAll();
                }
            }
        });

        t1.start();
        t2.start();
    }
}
```

---



## 🔑 Core Concept — `java.util.concurrent.Semaphore`

A **Semaphore** is a concurrency primitive that controls access using an internal **permit counter**.

|Method|Behaviour|
|---|---|
|`acquire()`|Blocks until a permit is available, then decrements the counter|
|`release()`|Increments the counter, unblocking any waiting thread|

Think of permits as **tokens** — a thread must hold a token to proceed, and hands it off when done.

---

## 🏗️ Setup — Two Semaphores, One Token Between Them

```java
Semaphore numberSem = new Semaphore(1); // starts with 1 permit → t1 goes first
Semaphore charSem   = new Semaphore(0); // starts with 0 permits → t2 must wait
```

The single permit starts with `numberSem`, meaning **only `t1` can run initially**. `t2` is blocked until `t1` hands the token over.

---

## 🔄 Execution Flow (Per Iteration)

```
t1 (number thread)           t2 (char thread)
─────────────────────        ──────────────────────
numberSem.acquire()  ──┐
  [has permit, runs]   │
  print(i)             │
charSem.release()  ────┼──►  charSem.acquire()
                       │       [now has permit]
                       │       print(ch)
                       │     numberSem.release()
numberSem.acquire()  ◄─┘
  [cycle repeats...]
```

### Step-by-step for first two iterations:

1. `t1` calls `numberSem.acquire()` → **succeeds** (permit = 1 → 0), prints `1`
2. `t1` calls `charSem.release()` → charSem permits = 0 → **1**
3. `t2` calls `charSem.acquire()` → **succeeds** (permit = 1 → 0), prints `A`
4. `t2` calls `numberSem.release()` → numberSem permits = 0 → **1**
5. `t1` calls `numberSem.acquire()` → **succeeds**, prints `2`
6. ... and so on until `26Z`

## 📋 Full Annotated Code

```java
import java.util.concurrent.Semaphore;

public class printSeqThread {

    public static void main(String[] args) {

        // numberSem starts with 1 permit → t1 runs first
        Semaphore numberSem = new Semaphore(1);

        // charSem starts with 0 permits → t2 is blocked initially
        Semaphore charSem = new Semaphore(0);

        // Thread 1: prints numbers 1–26
        Thread t1 = new Thread(() -> {
            for (int i = 1; i <= 26; i++) {
                try {
                    numberSem.acquire();    // wait for our turn
                    System.out.print(i);   // print the number
                    charSem.release();     // signal t2 to go
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
        });

        // Thread 2: prints letters A–Z
        Thread t2 = new Thread(() -> {
            for (char ch = 'A'; ch <= 'Z'; ch++) {
                try {
                    charSem.acquire();     // wait for our turn
                    System.out.print(ch);  // print the letter
                    numberSem.release();   // signal t1 to go
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
        });

        t1.start();
        t2.start();
    }
}
```

## 📌 Key Design Decisions

### Why two semaphores?

A single semaphore could prevent simultaneous access, but can't enforce **order**. Two semaphores act as a **baton hand-off**— one for each direction of the alternation.

### Why initial permits `(1, 0)`?

This is the **bootstrapping trick**. Setting `numberSem=1` and `charSem=0` guarantees `t1` always goes first, giving deterministic output every run.

### Why not use `synchronized` / `wait` / `notify`?

You could, but semaphores are:

- More readable for producer-consumer / hand-off patterns
- Less error-prone (no need to manually manage locks + condition variables)
- Naturally suited to **signaling between threads**

---

## ⚠️ Edge Cases & Pitfalls

|Scenario|What Happens|
|---|---|
|Both semaphores start at `1`|Both threads could print simultaneously → garbled output|
|Both semaphores start at `0`|Deadlock — neither thread can start|
|Forgetting `release()` in one thread|The other thread blocks forever (deadlock)|
|Not catching `InterruptedException`|Thread silently dies mid-sequence|

## 🧠 Mental Model — "Hot Potato"

Imagine a single hot potato (the permit) being passed back and forth:

```
[numberSem has potato] → t1 prints number → [passes potato to charSem]
[charSem has potato]   → t2 prints letter → [passes potato back to numberSem]
```

At any point, **exactly one thread holds the potato** and is allowed to print. The other must wait.

## 🔗 Related Patterns

- **Producer-Consumer** — one semaphore tracks empty slots, another tracks filled slots
- **Barrier synchronization** — multiple threads wait at a point until all arrive
- **Mutex (binary semaphore)** — semaphore with max 1 permit used for mutual exclusion
