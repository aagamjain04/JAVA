

## 1. What is an Exception?

An **Exception** is an event that occurs during the execution of a program that disrupts its normal flow.

- The JVM creates an **Exception Object** containing information about the error:
    - Name of the Exception
    - Message
    - Stack Trace
- The runtime system searches the **call stack** upward for a method that can handle it

### Call Stack Exception Propagation

```
method1() → method2() → method3()  ← exception thrown here
                                       ↓ can method3 handle? No
                         ↑ can method2 handle? No
           ↑ can method1 handle? No
↑ can main() handle? No
→ Runtime terminates program and prints stack trace
```

## 2. Exception Hierarchy

```
Throwable
├── Error               ← JVM-level, unrecoverable (OutOfMemoryError, StackOverflowError)
└── Exception
    ├── RuntimeException (Unchecked)
    │   ├── NullPointerException
    │   ├── ArithmeticException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ClassCastException
    │   ├── IllegalArgumentException
    │   └── NumberFormatException
    │
    └── (Checked Exceptions)
        ├── IOException
        ├── SQLException
        ├── ClassNotFoundException
        └── FileNotFoundException
```

## 3. Checked vs Unchecked Exceptions

||Checked|Unchecked (Runtime)|
|---|---|---|
|**When detected**|Compile time|Runtime|
|**Must handle?**|Yes — compiler forces you|No|
|**Extends**|`Exception` (not RuntimeException)|`RuntimeException`|
|**Examples**|`FileNotFoundException`, `ClassNotFoundException`|`NullPointerException`, `ArithmeticException`, `ArrayIndexOutOfBoundsException`|

## 4. Common Unchecked (Runtime) Exceptions

### `ClassCastException`

```java
Object val = "Hello";
Number num = (Number) val;  // ClassCastException at runtime
```

### `ArithmeticException`

```java
int val = 5 / 0;  // ArithmeticException: / by zero
```

### `ArrayIndexOutOfBoundsException`

```java
int[] arr = new int[5];
arr[10] = 3;  // ArrayIndexOutOfBoundsException: Index 10 out of bounds for length 5
```

### `StringIndexOutOfBoundsException`

```java
String s = "Hello";
System.out.println(s.charAt(10));  // StringIndexOutOfBoundsException: String index out of range: 10
```

### `NullPointerException`

```java
String s = null;
System.out.println(s.length());  // NullPointerException
```

### `IllegalArgumentException`

```java
int val = Integer.parseInt("abc");  // NumberFormatException (subclass of IllegalArgumentException)
```

## 5. Checked (Compile-Time) Exceptions

The compiler verifies these **during compilation** — if not handled, code will not compile.

```java
// This will NOT compile — ClassNotFoundException must be handled
public static void main(String[] args) {
    method1();
}
public static void method1() {
    Class.forName("SomeClass");   // throws ClassNotFoundException
}
```

### Two ways to handle a Checked Exception:

**Option 1: `throws` — declare and propagate**

```java
// "throws" tells the method: I might throw this, YOU handle it
public static void method1() throws ClassNotFoundException {
    Class.forName("SomeClass");
}

// Caller must then handle or propagate further
public static void main(String[] args) throws ClassNotFoundException {
    method1();
}
```

**Option 2: `try/catch` — handle it directly**

```java
public static void main(String[] args) {
    try {
        method1();
    } catch (ClassNotFoundException exceptionObj) {
        System.out.println(exceptionObj.getMessage());
    }
}
```

## 6. try / catch / finally / throw / throws

### 1. `try` / `catch`

- `try` block specifies code that can throw exceptions
- `catch` block handles the exception; can only catch exceptions thrown by its `try` block
- Multiple `catch` blocks are allowed
- **Important:** More specific exceptions must come BEFORE more general ones

```java
try {
    // risky code
} catch (IndexOutOfBoundsException e) {
    // handle specific exception first
} catch (Exception e) {
    // handle general exception last — catches anything else
}
```

**Catch multiple exceptions in one block (Java 7+):**

```java
catch (FileNotFoundException | ClassNotFoundException e) {
    // handle either
}
```

**Invalid — dead catch block (compile error):**

```java
catch (Exception e) { }         // catches everything
catch (IOException e) { }       // ← compile error: already caught above
```

---

### 2. `try` / `finally` or `try` / `catch` / `finally`

- `finally` block **always executes** — whether or not an exception occurs
- At most 1 `finally` block per try
- Used for: closing objects, adding logs, cleanup
- **Exception:** If JVM runs out of memory or system shuts down forcefully, `finally` may NOT execute

```java
try {
    // code
} catch (Exception e) {
    // handle
} finally {
    // ALWAYS runs — close resources, cleanup
}
```

---

### 3. `throw`

- Used to **manually throw** a new exception or re-throw a caught one

```java
public static void method1() throws ClassNotFoundException {
    try {
        // code
    } catch (ClassNotFoundException e) {
        throw e;   // re-throw
    }
}

// Throw a new exception
public static void method1() throws ClassNotFoundException {
    throw new ClassNotFoundException("not found");
}
```

---

### 4. `throws`

- Used in a method signature to **declare** that this method might throw a checked exception
- Caller is then responsible for handling it

```java
public void myMethod() throws FileNotFoundException, ClassNotFoundException {
    // ...
}
```

> **Interview distinction:** `throw` is used to actually throw an exception instance. `throws` is used in the method signature to declare what exceptions a method might propagate.

## 7. Custom / User-Defined Exception Classes

Create your own exception by extending `Exception` (checked) or `RuntimeException` (unchecked).

```java
public class MyCustomException extends Exception {
    MyCustomException(String message) {
        super(message);   // passes message to Exception's constructor
    }
}

// Using it
public class Main {
    public static void main(String[] args) {
        try {
            method1();
        } catch (MyCustomException e) {
            System.out.println(e);
        }
    }

    public static void method1() throws MyCustomException {
        throw new MyCustomException("some error");
    }
}
```

> **Why custom exceptions?** They make code cleaner by separating error-handling from regular logic, allow richer error information, and improve security by hiding sensitive internal details.

## 8. Why Handle Exceptions? (The "Why Bother" Answer)

Without exception handling, a method must return **two things**: the actual result AND an error code — making the caller's code messy.

```java
// Without exception handling — ugly
public int myMethod(int schoolClassNumber) {
    int errorCode = 0;
    if (isValid(schoolClassNumber) != -1 && schoolClassNumber >= 1) {
        int noOfStudents = getStudentCapacityofClass(schoolClassNumber);
        try {
            String[] names = new String[noOfStudents];
            names[0] = "new value";
        } catch (...) { errorCode = -1; }
    } else { errorCode = -1; }
    return errorCode;
}

// With exception handling — clean
public void myMethod(int schoolClassNumber) {
    try {
        int noOfStudents = getStudentCapacityofClass(schoolClassNumber);
        String[] names = new String[noOfStudents];
        names[0] = "new value";
    } catch (IndexOutOfBoundsException e) {
        // handle
    } catch (Exception e) {
        // handle all others
    }
}
```

**Benefits of exception handling:**

- Separates error-handling code from regular logic → cleaner, more readable
- Allows the program to recover from errors gracefully
- Provides more information to aid debugging
- Improves security by hiding sensitive implementation details from callers

## 9. Performance Note

> Exception handling has a **performance cost** — especially when the stack trace is large or the exception is handled at a distant parent class.

**Prefer prevention over catching where possible:**

```java
// Worse — uses exception handling unnecessarily
public int divide(int a, int b) {
    int val;
    try {
        val = a / b;
    } catch (ArithmeticException e) {
        val = -1;
    }
    return val;
}

// Better — guard with a condition instead
public int divide(int a, int b) {
    if (b == 0) return -1;
    return a / b;
}
```

## 10. Quick-Reference Cheat Sheet

```
Keywords:
  try     → wraps risky code
  catch   → handles a specific exception type (can have multiples)
  finally → always runs; used for cleanup (max 1 per try)
  throw   → throws an exception instance (e.g. throw new MyException())
  throws  → declares in method signature what might be thrown

Order of catch blocks:
  SPECIFIC → GENERAL  (child class before parent class)

Custom exception:
  extend Exception       → checked (caller must handle)
  extend RuntimeException → unchecked (caller does not have to handle)

Must-handle check:
  Checked exceptions → handle with try/catch OR declare with throws
  Unchecked exceptions → optional (but good practice to handle)
```

## 11. Common Interview Questions

**Q: What is the difference between `Error` and `Exception`?**

> `Error` represents serious JVM-level problems (e.g., `OutOfMemoryError`, `StackOverflowError`) that are generally unrecoverable and should not be caught. `Exception` represents conditions a program can reasonably handle.

**Q: What is the difference between checked and unchecked exceptions?**

> Checked exceptions are verified at compile time — the compiler forces you to handle or declare them. Unchecked (runtime) exceptions extend `RuntimeException` and are not checked at compile time.

**Q: What is the difference between `throw` and `throws`?**

> `throw` is used inside a method body to actually throw an exception instance. `throws` is used in the method signature to declare that the method may throw a checked exception, putting responsibility on the caller.

**Q: Does `finally` always execute?**

> Almost always — it runs whether an exception is thrown or not. Exceptions: if `System.exit()` is called, if the JVM crashes, or if the thread is killed forcefully.

**Q: Can you catch multiple exceptions in one catch block?**

> Yes (Java 7+), using the pipe operator: `catch (IOException | ClassNotFoundException e) { }`

**Q: What is the correct order of multiple catch blocks?**

> More specific (child) exceptions must appear before more general (parent) ones. A `catch(Exception e)` before a `catch(IOException e)` causes a compile error — the IOException block is unreachable.

**Q: When should you create a custom exception?**

> When you need to represent a domain-specific error condition, when you want to add additional fields/methods to the exception, or when you want to provide cleaner error messages to callers while hiding internal implementation details.

**Q: What is the difference between `final`, `finally`, and `finalize`?**

> `final` is a keyword for constants/non-overridable methods/classes. `finally` is the always-executed block in try-catch. `finalize` is a method called by the GC before object cleanup (deprecated in Java 9+).
