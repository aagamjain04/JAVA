## 1. The Problem — Tracking Async Task Status

```java
// Without Future — no way to check if task finished or what it returned
poolExecutor.submit(() -> {
    System.out.println("this is the task, which thread will execute");
});
// main thread continues but has NO handle on the submitted task
// → How do you know if it completed? Failed? What did it return?
```

## 2. `Future<V>` Interface

`Future<V>` is an **interface** that represents the result of an **async task**.

- Allows you to check:
    - Whether **computation is complete**
    - **Get the result** (blocks until done)
    - **Handle exceptions** if any

### Future Methods:

|Method|Purpose|
|---|---|
|`boolean cancel(boolean mayInterruptIfRunning)`|Attempts to cancel execution. Returns `false` if task already completed (can't cancel); `true` otherwise.|
|`boolean isCancelled()`|Returns `true` if the task was cancelled before it completed.|
|`boolean isDone()`|Returns `true` if task completed — by normal termination, exception, OR cancellation.|
|`V get()`|**Blocks** until task completes, then retrieves the result.|
|`V get(long timeout, TimeUnit unit)`|Blocks for **at most** the given timeout. Throws `TimeoutException` if not done in time.|

### Code Example:

```java
ThreadPoolExecutor poolExecutor = new ThreadPoolExecutor(1, 1, 1, TimeUnit.HOURS,
    new ArrayBlockingQueue<>(10), Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.AbortPolicy());

// Submit task and get a Future handle
Future<?> futureObj = poolExecutor.submit(() -> {
    try {
        Thread.sleep(7000);
        System.out.println("this is the task, which thread will execute");
    } catch (Exception e) {}
});

System.out.println("is Done: " + futureObj.isDone());  // false (still running)

try {
    futureObj.get(2, TimeUnit.SECONDS);  // wait at most 2 seconds
} catch (TimeoutException e) {
    System.out.println("TimeoutException happened");  // thrown after 2s
}

try {
    futureObj.get();  // blocks until task completes (7s total)
} catch (Exception e) {}

System.out.println("is Done: " + futureObj.isDone());       // true
System.out.println("is Cancelled: " + futureObj.isCancelled()); // false
```

## 3. `Callable<V>` Interface

`Callable<V>` represents a **task** to be executed — like `Runnable` but with a **return value** and can throw checked exceptions.

### Runnable vs Callable:

```java
// Runnable — no return value
@FunctionalInterface
public interface Runnable {
    public abstract void run();
}

// Callable — has return value V, can throw Exception
@FunctionalInterface
public interface Callable<V> {
    V call() throws Exception;
}
```

||`Runnable`|`Callable<V>`|
|---|---|---|
|Return type|`void` — no return|`V` — returns a value|
|Exception|Cannot throw checked exceptions|Can throw checked `Exception`|
|Submit via|`executor.submit(runnable)`|`executor.submit(callable)`|
|Result via|`Future<?>` (result is null)|`Future<V>` (result is V)|

### Three Callable use-cases with Future:

```java
ThreadPoolExecutor poolExecutor = new ThreadPoolExecutor(3, 3, 1, TimeUnit.HOURS,
    new ArrayBlockingQueue<>(10), Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.AbortPolicy());

// UseCase 1: Runnable — Future result is null
Future<?> futureObject1 = poolExecutor.submit(() -> {
    System.out.println("Task1 with Runnable");
});
Object object = futureObject1.get();
System.out.println(object == null);  // true

// UseCase 2: Runnable with shared output object (workaround for return)
List<Integer> output = new ArrayList<>();
Future<List<Integer>> futureObject2 = poolExecutor.submit(() -> {
    output.add(100);
    System.out.println("Task2 with Runnable and Return object");
}, output);   // pass the output list as the result object
List<Integer> outputFromFutureObject2 = futureObject2.get();
System.out.println(outputFromFutureObject2.get(0));  // 100

// UseCase 3: Callable — proper return value
Future<List<Integer>> futureObject3 = poolExecutor.submit(() -> {
    System.out.println("Task3 with Callable");
    List<Integer> listObj = new ArrayList<>();
    listObj.add(200);
    return listObj;  // ← Callable returns value
});
List<Integer> outputFromFutureObject3 = futureObject3.get();
System.out.println(outputFromFutureObject3.get(0));  // 200
```

## 4. `CompletableFuture`

### What is it?

- Introduced in **Java 8**.
- Helps with **async programming**.
- An **advanced version of `Future`** — adds chaining, combining, and composition of async tasks.
- `Future` is blocking; `CompletableFuture` supports **non-blocking pipelines**.

### How to create:

```java
// Without executor (uses Fork-Join pool by default)
public static <T> CompletableFuture<T> supplyAsync(Supplier<T> supplier)

// With custom executor
public static <T> CompletableFuture<T> supplyAsync(Supplier<T> supplier, Executor executor)
```

- `supplyAsync` initiates an **Async operation**.
- `supplier` is executed asynchronously in a separate thread.
- By default uses the shared **Fork-Join Pool** (dynamically adjusts pool size based on processors).

---

## 5. CompletableFuture Methods

### Method 1: `supplyAsync`

```java
CompletableFuture<String> asyncTask1 = CompletableFuture.supplyAsync(() -> {
    // task executed in a thread pool thread
    return "task completed";
}, poolExecutor);

System.out.println(asyncTask1.get());  // "task completed"
```

---

### Method 2: `thenApply` & `thenApplyAsync`

- **Applies a function** to the result of the previous async computation.
- **Returns a new `CompletableFuture`** object — enabling chaining.

```java
CompletableFuture<String> asyncTask1 = CompletableFuture
    .supplyAsync(() -> {
        return "Concept and ";
    }, poolExecutor)
    .thenApply((String val) -> {
        // works on result of previous async task
        return val + "Coding";
    });
// result: "Concept and Coding"
```

#### `thenApply` vs `thenApplyAsync`:

||`thenApply`|`thenApplyAsync`|
|---|---|---|
|Execution|**Synchronous** — runs on same thread that completed the previous task|**Asynchronous** — runs on a different thread (Fork-Join pool if no executor passed)|
|Ordering|Guaranteed order|If multiple `thenApplyAsync`, ordering **cannot be guaranteed**(concurrent)|

**Output demonstration:**

```
Thread Name which runs 'supplyAsync': pool-1-thread-1
Thread Name for 'after CF': main
Thread Name which runs 'thenApply': ForkJoinPool.commonPool-worker-9
```

---

### Method 3: `thenCompose` & `thenComposeAsync`

- **Chains together dependent async operations**.
- Use when the next async operation depends on the result of the previous async one.
- Brings **ordering** to async task chains (unlike `thenApplyAsync`).

```java
CompletableFuture<String> asyncTask1 = CompletableFuture
    .supplyAsync(() -> {
        System.out.println("Thread Name which runs 'supplyAsync': " + Thread.currentThread().getName());
        return "Concept and ";
    }, poolExecutor)
    .thenCompose((String val) -> {
        return CompletableFuture.supplyAsync(() -> {
            System.out.println("Thread Name which runs 'thenCompose': " + Thread.currentThread().getName());
            return val + "Coding";
        });
    });
```

#### `thenApply` vs `thenCompose`:

||`thenApply`|`thenCompose`|
|---|---|---|
|Input function returns|A value `T`|A `CompletableFuture<T>`|
|Use for|Simple transformation|Chaining async operations that return futures|
|Analogy|`map()` in Stream|`flatMap()` in Stream|

---

### Method 4: `thenAccept` & `thenAcceptAsync`

- **Terminal/end stage** of the async chain.
- **Does NOT return anything** (returns `CompletableFuture<Void>`).
- Used for **consuming** the result (e.g., print, save, send).

```java
CompletableFuture<Void> asyncTask1 = CompletableFuture
    .supplyAsync(() -> {
        System.out.println("Thread Name which runs 'supplyAsync': " + Thread.currentThread().getName());
        return "Concept and ";
    }, poolExecutor)
    .thenAccept((String val) -> System.out.println("All stages completed"));
// "All stages completed" — consumes the result, returns void
```

---

### Method 5: `thenCombine` & `thenCombineAsync`

- **Combines the result of 2 independent `CompletableFuture`s**.
- Both run concurrently; `thenCombine` waits for both to finish then applies the combiner function.

```java
CompletableFuture<Integer> asyncTask1 = CompletableFuture
    .supplyAsync(() -> {
        return 10;
    }, poolExecutor);

CompletableFuture<String> asyncTask2 = CompletableFuture
    .supplyAsync(() -> {
        return "k ";
    }, poolExecutor);

CompletableFuture<String> combinedFutureObj = asyncTask1
    .thenCombine(asyncTask2, (Integer val1, String val2) -> val1 + val2);
// result: "10k"
```

## 6. CompletableFuture — Method Summary

|Method|Returns|Description|
|---|---|---|
|`supplyAsync(supplier)`|`CF<T>`|Start async task, returns value|
|`thenApply(fn)`|`CF<R>`|Transform result (sync, same thread)|
|`thenApplyAsync(fn)`|`CF<R>`|Transform result (async, different thread)|
|`thenCompose(fn→CF)`|`CF<R>`|Chain dependent async tasks (flatMap equivalent)|
|`thenAccept(consumer)`|`CF<Void>`|Consume result, no return (terminal)|
|`thenAcceptAsync(consumer)`|`CF<Void>`|Consume result async, no return|
|`thenCombine(cf2, fn)`|`CF<R>`|Combine 2 independent futures|
|`thenCombineAsync(cf2, fn)`|`CF<R>`|Combine 2 futures asynchronously|
|`exceptionally(fn)`|`CF<T>`|Handle exception, return fallback value|
|`allOf(cf1, cf2, ...)`|`CF<Void>`|Wait for ALL futures to complete|
|`anyOf(cf1, cf2, ...)`|`CF<Object>`|Complete when ANY future completes|

## 7. Future vs CompletableFuture

||`Future`|`CompletableFuture`|
|---|---|---|
|Java version|Java 5|Java 8|
|Chaining|❌ No|✅ Yes|
|Combining futures|❌ No|✅ Yes (`thenCombine`, `allOf`)|
|Exception handling|❌ Limited (`get()` throws)|✅ `exceptionally()`, `handle()`|
|Non-blocking|❌ `get()` blocks|✅ callback-based|
|Manual completion|❌ No|✅ `complete()`, `completeExceptionally()`|

## 8. Common Interview Questions

**Q1. What is `Future` in Java? What are its limitations?**

> `Future<V>` represents the result of an async computation — lets you check if done, cancel it, or retrieve the result via `get()`. Limitations: `get()` is **blocking**, no chaining, no combining, no built-in exception handling, no way to manually complete.

**Q2. What is the difference between `Runnable` and `Callable`?**

> `Runnable.run()` returns `void` and cannot throw checked exceptions. `Callable.call()` returns a value of type `V` and can throw checked `Exception`. Both can be submitted to an `ExecutorService`; `Callable` gives you a meaningful `Future<V>`.

**Q3. What is `CompletableFuture`? How is it better than `Future`?**

> `CompletableFuture` (Java 8) is an advanced `Future` with chaining (`thenApply`, `thenCompose`), combining (`thenCombine`, `allOf`), exception handling (`exceptionally`), and non-blocking callbacks. `Future.get()` always blocks; `CompletableFuture`allows fully non-blocking async pipelines.

**Q4. What is the difference between `thenApply` and `thenCompose`?**

> Both chain operations after an async task. `thenApply` takes a function `T → R` and wraps the result in a new `CompletableFuture<R>` — like `map()`. `thenCompose` takes a function `T → CompletableFuture<R>` — like `flatMap()`. Use `thenCompose` when the next step is itself async (returns a `CompletableFuture`), otherwise `thenCompose` would give a nested `CompletableFuture<CompletableFuture<R>>`.

**Q5. What is the difference between `thenApply` and `thenApplyAsync`?**

> `thenApply` runs on the **same thread** that completed the previous stage (synchronous). `thenApplyAsync` runs on a **different thread** from the Fork-Join pool (or provided executor). Multiple `thenApplyAsync` calls can run concurrently — ordering is not guaranteed.

**Q6. What does `thenAccept` do? When do you use it?**

> `thenAccept` is a **terminal stage** — it consumes the result of the previous stage but returns `CompletableFuture<Void>`. Use it when you want to perform a side effect (print, save to DB, send notification) at the end of an async pipeline without returning a value.

**Q7. What is `thenCombine` used for?**

> `thenCombine` combines the results of **two independent `CompletableFuture`s** once both complete. Both run concurrently; when both finish, the combiner `BiFunction` is applied to their results.

**Q8. What executor does `CompletableFuture.supplyAsync()` use by default?**

> By default it uses the **shared Fork-Join Common Pool** (`ForkJoinPool.commonPool()`), which dynamically adjusts its size based on the number of available processors. You can pass a custom `Executor` as the second argument to use your own thread pool.
