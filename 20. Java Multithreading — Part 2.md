## 1. Thread Creation — 2 Ways

```
Thread Creation Ways
        |
   _____|_____
  |           |
Implementing  Extending
'Runnable'    'Thread'
interface     class
```

### Why 2 ways?

- A class can **implement more than 1 interface** → `Runnable` preferred when your class already extends something else.
- A class can **extend only 1 class** → `Thread` extension sacrifices inheritance flexibility.

> ✅ **Prefer `Runnable`** in most cases — better design, more flexible.

## 2. Way 1 — Implementing `Runnable` Interface

### UML

```
<<interface>>
  Runnable
   run()
     |
  implements        implements
     |                  |
  Thread            MyClass
  init()             run()    ← must override
  run()
  sleep()
  start()
  stop()
  interrupt()
  etc.
```

### Step 1 — Create a Runnable Object

- Create a class that `implements Runnable`.
- Override the `run()` method — this is the task the thread will execute.

```java
public class MultithreadingLearning implements Runnable {

    @Override
    public void run() {
        System.out.println("code executed by thread: " + Thread.currentThread().getName());
    }
}
```

### Step 2 — Start the Thread

- Create an instance of the class that implements `Runnable`.
- Pass the Runnable object to the **Thread constructor**.
- Call `start()` to begin execution.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Going inside main method: " + Thread.currentThread().getName());

        MultithreadingLearning runnableObj = new MultithreadingLearning();
        Thread thread = new Thread(runnableObj);
        thread.start();

        System.out.println("Finish main method: " + Thread.currentThread().getName());
    }
}
```

**Output:**

```
Going inside main method: main
Finish main method: main
code executed by thread: Thread-0
```

> ⚠️ Note: `main` finishes before `Thread-0` — threads run **concurrently**, order is not guaranteed.

## 3. Way 2 — Extending `Thread` Class

### UML

```
<<interface>>
  Runnable
   run()
     |
  implements
     |
  Thread
  init(), run(), sleep(), start(), stop(), interrupt(), etc.
     |
  extends
     |
  MyClass
   run()    ← override
```

### Step 1 — Create a Thread Subclass

- Create a class that `extends Thread`.
- Override the `run()` method.

```java
public class MultithreadingLearning extends Thread {

    @Override
    public void run() {
        System.out.println("code executed by thread: " + Thread.currentThread().getName());
    }
}
```

### Step 2 — Instantiate and Start the Thread

- Create an instance of the subclass.
- Call `start()` to begin execution.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Going inside main method: " + Thread.currentThread().getName());

        MultithreadingLearning myThread = new MultithreadingLearning();
        myThread.start();

        System.out.println("Finish main method: " + Thread.currentThread().getName());
    }
}
```

**Output:**

```
Going inside main method: main
Finish main method: main
code executed by thread: Thread-0
```

## 4. Runnable vs Thread — Comparison

||`implements Runnable`|`extends Thread`|
|---|---|---|
|**Inheritance**|Class can still extend another class ✅|Class cannot extend anything else ❌|
|**Coupling**|Task and thread mechanism are decoupled ✅|Task is tightly coupled to Thread class|
|**Reusability**|Same Runnable can be passed to multiple threads|Each subclass is one thread|
|**Preferred?**|✅ Yes|Only for simple cases|

## 5. Thread Lifecycle (State Machine)

```
                    stop()              stop()
                ┌─────────────────────────────────┐
                │                                  │
  [New] ─start()→ [Runnable] ─run()→ [Running] ─Run() finishes→ [Terminated]
                  (waiting      ←yield()  (got CPU)
                  for CPU)
                     │                   │
               I/O task or          wait()  ──────────→ [Waiting]
               acquire lock         sleep()/join() ───→ [Timed Waiting]
                     │                                        │
                     ↓                              sleep time expires/
                 [Blocked]                          join complete → Runnable
                     │
               I/O done /
               lock acquired → Runnable
```

> `stop()` from **any** state leads to **Terminated**.

## 6. Thread Lifecycle States — Explained

|State|Description|
|---|---|
|**New**|Thread has been created but not started. It's just an Object in memory.|
|**Runnable**|Thread is ready to run. Waiting for CPU time.|
|**Running**|When thread starts executing its code (got CPU).|
|**Blocked**|Different scenarios where a runnable thread goes into blocking state: **I/O** (like reading from file or DB), **Lock acquired** (if thread wants to lock a resource which is locked by another thread — it has to wait). Releases all **MONITOR LOCKS**.|
|**Waiting**|Thread goes into this state when `wait()` is called — makes it non-runnable. Goes back to runnable once `notify()` or `notifyAll()` is called. Releases all **MONITOR LOCKS**.|
|**Timed Waiting**|Thread waits for a specific period of time and comes back to runnable after specific conditions met. Triggered by `sleep()`, `join()`. Does **NOT** release MONITOR LOCKS.|
|**Terminated**|Life of thread is completed. It **cannot be started back again**.|

## 7. Monitor Lock (Synchronized Block)

> **Monitor Lock** ensures that only **1 thread** enters a particular section of code (a synchronized block or method) at a time.

### Key Behaviours:

- `Blocked` state → thread **releases** monitor lock (waiting for lock held by another)
- `Waiting` state → thread **releases** monitor lock (called `wait()`)
- `Timed Waiting` state → thread **does NOT release** monitor lock (sleeping/joining)

### Code Example — Monitor Lock in action

```java
public class MonitorLockExample {

    // Synchronized method — only 1 thread at a time
    public synchronized void task1() {
        try {
            // Do something
            Thread.sleep(1000);
        } catch (Exception e) {
            // exception handling
        }
    }

    public void task2() {
        System.out.println("task2, but before synchronized");
        synchronized (this) {
            System.out.println("task2, inside synchronized");
        }
    }

    public void task3() {
        System.out.println("task3");
    }
}

public static void main(String[] args) {
    MonitorLockExample obj = new MonitorLockExample();

    Thread t1 = new Thread(() -> obj.task1());
    Thread t2 = new Thread(() -> obj.task2());
    Thread t3 = new Thread(() -> obj.task3());

    t1.start();
    t2.start();
    t3.start();
}
```

> `t1` holds the lock on `obj` → `t2` must wait for `task1()` to finish before entering its `synchronized(this)` block. `t3` is not synchronized so it runs freely.

## 8. Producer-Consumer Pattern (Example)

A classic multithreading example showing thread cooperation via a shared resource.

```java
class SharedResource {
    int value = 0;
    boolean hasValue = false;
}

class ProduceTask implements Runnable {
    SharedResource resource;

    ProduceTask(SharedResource resource) {
        this.resource = resource;
    }

    @Override
    public void run() {
        // ... synchronized, wait/notify logic to produce
        System.out.println("Produced value: " + Thread.currentThread().getName());
        Thread.sleep(1000);
        resource.value++;
    }
}

class ConsumeTask implements Runnable {
    SharedResource resource;

    ConsumeTask(SharedResource resource) {
        this.resource = resource;
    }

    @Override
    public void run() {
        System.out.println("Consumer thread: " + Thread.currentThread().getName());
        resource.consumeItem();
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("Main method start");

        SharedResource sharedResource = new SharedResource();

        // Producer thread
        Thread producerThread = new Thread(new ProduceTask(sharedResource));
        // Consumer thread
        Thread consumerThread = new Thread(new ConsumeTask(sharedResource));

        // IS in "runnable" thread
        producerThread.start();
        consumerThread.start();

        System.out.println("Main method end");
    }
}
```

**Lambda shorthand (avoid creating ProduceTask and ConsumeTask classes):**

```java
Thread consumerThread = new Thread(() -> {
    System.out.println("Consumer thread: " + Thread.currentThread().getName());
    sharedResource.consumeItem();
});
```

## 9. Assignment — Producer Consumer Problem

**Question:**

> Two threads, a producer and a consumer, share a common fixed-size buffer as a queue.
> 
> - **Producer's job:** generate data and put it into the buffer.
> - **Consumer's job:** consume the data from the buffer.
> - **Problem:** ensure the producer won't produce data if the buffer is **full**, and the consumer won't consume data if the buffer is **empty**.

_(This is the classic `wait()` / `notify()` problem — solve using `synchronized`, `wait()`, `notifyAll()`)_

```java
// Skeleton solution
class SharedBuffer {
    private int[] buffer;
    private int count = 0;
    private int capacity;

    SharedBuffer(int capacity) { this.capacity = capacity; buffer = new int[capacity]; }

    public synchronized void produce(int value) throws InterruptedException {
        while (count == capacity) wait();  // buffer full → wait
        buffer[count++] = value;
        System.out.println("Produced: " + value);
        notifyAll();  // notify consumer
    }

    public synchronized int consume() throws InterruptedException {
        while (count == 0) wait();  // buffer empty → wait
        int value = buffer[--count];
        System.out.println("Consumed: " + value);
        notifyAll();  // notify producer
        return value;
    }
}
```

## 10. Common Interview Questions

**Q1. What are the two ways to create a thread in Java?**

> (1) Implement `Runnable` interface and pass to `Thread` constructor. (2) Extend `Thread` class and override `run()`. `Runnable` is preferred because a class can implement multiple interfaces but can only extend one class.

**Q2. What is the difference between `start()` and `run()`?**

> `start()` creates a new thread and calls `run()` in that new thread. If you call `run()` directly, it executes in the **current thread** (no new thread created) — just a regular method call.

**Q3. What are all the thread lifecycle states?**

> New → Runnable → Running → (Blocked / Waiting / Timed Waiting) → Terminated.

**Q4. What is the difference between `Waiting` and `Timed Waiting`?**

> `Waiting` (via `wait()`) waits indefinitely until `notify()`/`notifyAll()`. `Timed Waiting` (via `sleep()`, `join()`) waits for a specific time period. Critically: `Waiting` **releases** monitor lock; `Timed Waiting` does **NOT** release monitor lock.

**Q5. What is a Monitor Lock?**

> A monitor lock ensures only one thread executes a synchronized block/method on a given object at a time. Other threads wanting the lock go to `Blocked` state.

**Q6. What happens when `stop()` is called on a thread?**

> The thread moves directly to `Terminated` state from any state (New, Runnable, Blocked, Waiting, Timed Waiting). Note: `stop()` is **deprecated** — use a volatile flag or `interrupt()` instead.

**Q7. What is `yield()` in threads?**

> `yield()` causes the currently running thread to move back from `Running` to `Runnable`, giving other threads of the same priority a chance to run. The scheduler may or may not honour it.

**Q8. What is the difference between `Blocked` and `Waiting` states?**

> `Blocked` — thread is waiting to **acquire a lock** (lock is held by another thread). `Waiting` — thread has **released the lock** and is waiting to be notified via `notify()`/`notifyAll()`. Both release the monitor lock, but the trigger and recovery mechanism differ.

**Q9. Can a terminated thread be restarted?**

> No. Once a thread reaches the `Terminated` state, it cannot be started again. You must create a new thread instance.

**Q10. What is the Producer-Consumer problem?**

> A synchronization problem where a producer thread adds items to a shared buffer and a consumer thread removes them. The challenge is: producer must wait when buffer is full; consumer must wait when buffer is empty. Solved using `synchronized`, `wait()`, and `notifyAll()`.
