
# Java Collections

---

## 1. What is the Java Collections Framework?

- Added in **Java version 1.2**
- A collection is nothing but a **group of Objects**
- The framework provides the **architecture** to manage groups of objects: add, update, delete, search, etc.

### Why we need it — The Problem Before Collections

Prior to JCF we had **Array**, **Vector**, **Hash Tables** — but no common interface, making it difficult to remember methods for each.

## 3. Iterable Interface

- Used to **traverse** (iterate) a collection
- Key methods:

|Method|Returns|Description|
|---|---|---|
|`iterator()`|`Iterator`|Returns the Iterator object (which provides methods to iterate the Collection)|
|`forEach()`|`void`|Iterates Collection using lambda expression; the lambda is called for each element|

---

## 4. Collection Interface

Represents the group of objects. Provides methods to work on that group.

|#|Method|Level|Description|
|---|---|---|---|
|1|`size()`|level 2|Returns total number of elements|
|2|`contains(element)`|level 2|Checks if element is in collection; returns `true`/`false`|
|3|`add(element)`|level 2|Converts element into Array|
|4|`remove(element)`|level 2|Used to remove an element|
|5|`removeAll(collection)`|level 2|Removes all elements from collection which are present in the argument collection|
|6|`isEmpty()`|level 2|Returns `true` if collection is empty|
|7|`equals()`|level 2|Used to check if 2 collections are equal|
|8|`toArray()`|level 2|Provides effective way to work with collection-like filtering, processing data etc.|
|9|`stream()`|level 2|An Iterator interface added in Java 8; to iterate this|
|10|`iterator()`|level 2|This method was used to iterate the collection and still can be used|

### Collections Utility Class (different from Collection interface!)

`Collections` is a **utility class** — provides static methods to operate on collections:

- `sort()`, `min()`, `max()`, `copy()`, `fill()`, `frequency()`, `reverse()`, `shuffle()`, etc.

## 5. List Interface

- **Ordered** collection of objects; **duplicate values are allowed**
- Data can be inserted, removed, or accessed by **index** (starting from 0)
- User can decide where to insert or access using index

### New Methods defined in List (in addition to Collection methods):

|#|Method|Description|
|---|---|---|
|1|`add(index, element)`|Insert the element at the specific position or the list. If there's any element present at that position, it shift it to the right|
|2|`addAll(index, collection)`|Insert all the elements of the specific collection into the list from index, with the adjacent element corresponding to the right|
|3|`get(index)`|Returns the element at the specified position in the list|
|4|`remove(index)`|Removes the element from the index value provided and shifts all subsequent elements to the left|
|5|`set(index, value)`|Replaces the element at the specified index in the list with the element provided|
|6|`indexOf(value)`|Returns the index of the first occurrence of the specified element in the list. Returns -1 if element not found|
|7|`lastIndexOf(value)`|Returns the index of the last occurrence of the specified element in the list. Returns -1 if element not found|

### `ListIterator` (bonus iterator for List):

- Can iterate both **forward and backward** (unlike regular Iterator which is forward-only)
- Use `listIterator(index)` to start from a specific index
- If `fromIndex == toIndex`, start iterator will be empty; call `change()` to modify elements during iteration

## 6. ArrayList

- **Dynamic array** — resizes automatically
- Maintains **insertion order**
- Allows **null** elements and **duplicates**
- **NOT thread-safe**

```java
ArrayList<String> list = new ArrayList<>();
list.add("hatchback");
list.add("sedan");
list.add("suv");

// Iterate using Iterator
Iterator<String> iterator = list.iterator();
while (iterator.hasNext()) {
    System.out.println(iterator.next());
}

// Iterate using forEach
list.forEach(val -> System.out.println(val));

// Iterate using for-each loop
for (String val : list) {
    System.out.println(val);
}
```

**Output:** hatchback, sedan, suv (insertion order preserved)

**Time Complexity:**

- Add O(1) — amortised
- Get O(1)
- Remove O(n)
- Search O(n)

**Space Complexity:** O(n)

---

## 7. LinkedList

- Data structure used to **insert List**
- Implements both **List** and **Deque** interfaces
- A **doubly linked list** — each node has `prev`, `data`, `next` pointers
- Allows: `"generic"`, `"transient"`, `"serializable"` etc.

```java
LinkedList<Integer> list = new LinkedList<>();
list.add(100);
list.add(200);
list.add(300);
System.out.println(list.get(0));  // 100
```

**Time Complexity:**

- Add/remove at head/tail: O(1)
- Add/remove at index: O(n)
- Search: O(n)

**Space Complexity:** O(n)

## 8. Queue Interface

- FIFO — **First In, First Out** (remove from front, insert at rear)
- Child of Collection interface
- Generally Queue follows FIFO, but exceptions like **PriorityQueue** exist

### Queue Methods:

|#|Method|Description|
|---|---|---|
|1|`add()`|Insert element into queue. Returns `true` if successful; throws **Exception** if insertion fails. Null element insertion not allowed — throws **NPE**|
|2|`offer()`|Insert element into queue. Returns `true` if successful and **`false`** if insertion fails (safer than `add`). Null not allowed — throws **NPE**|
|3|`poll()`|Retrieves AND removes the head of the queue. Returns **null** if Queue is empty|
|4|`remove()`|Retrieves AND removes the head of the queue. Throws **NoSuchElementException** if Queue is empty|
|5|`peek()`|Retrieves value at head of queue but does NOT remove. Returns **null** if Queue is empty|
|6|`element()`|Retrieves value at head of queue but does NOT remove. Throws **NoSuchElementException** if Queue is empty|

> **Key interview distinction:**
> 
> - `add()` vs `offer()` → both insert, but `add` throws exception on failure, `offer` returns `false`
> - `remove()` vs `poll()` → both remove head, but `remove` throws exception if empty, `poll` returns `null`
> - `element()` vs `peek()` → both peek at head, but `element` throws exception if empty, `peek` returns `null`

## 9. PriorityQueue

- Elements are ordered according to **natural ordering** (by default) or by a **Comparator** provided at queue construction time
- **2 types:** Min Priority Queue and Max Priority Queue
- It is based on priority heap (Min Heap and Max Heap)

### Min Priority Queue (natural ordering — smallest first)

```java
PriorityQueue<Integer> queue = new PriorityQueue<>();
queue.add(5); queue.add(1); queue.add(3); queue.add(2); queue.add(4);
while (!queue.isEmpty()) {
    System.out.println("remove from top: " + queue.poll());
}
// Output: 1, 2, 3, 4, 5
```

### Max Priority Queue (using Comparator)

```java
PriorityQueue<Integer> maxPQ = new PriorityQueue<>(Collections.reverseOrder());
// OR
PriorityQueue<Integer> maxPQ = new PriorityQueue<>((a, b) -> b - a);
// Output: 5, 4, 3, 2, 1
```

**Time Complexity:**

- Add/Offer: O(log n)
- Remove: O(log n)
- Retrieve arbitrary element: O(n)

**Space Complexity:** O(n)

## 10. Comparator vs Comparable

Both provide a way to sort collections of objects.

||Comparator|Comparable|
|---|---|---|
|**Package**|`java.util`|`java.lang`|
|**Method**|`compare(obj1, obj2)`|`compareTo(obj)`|
|**Where implemented**|Separate class (external)|Inside the class itself|
|**Modifies original class?**|No|Yes|
|**Multiple sort orders?**|Yes — create multiple Comparators|No — one natural order|

### Comparable — class implements it:

```java
public class Car implements Comparable<Car> {
    String carName;
    String carType;
    @Override
    public int compareTo(Car s1) {
        return s1.carName.compareTo(this.carName);
    }
}
// Usage:
Collections.sort(cars);  // uses compareTo automatically
```

### Comparator — separate class or lambda:

```java
// Separate class
public class CarNameComparator implements Comparator<Car> {
    @Override
    public int compare(Car c1, Car c2) {
        return c1.carName.compareTo(c2.carName);
    }
}
// Usage:
Collections.sort(cars, new CarNameComparator());

// Or with lambda:
Collections.sort(cars, (Car val1, Car val2) -> val1.carName.compareTo(val2.carName));
```

**Sorting algorithm used:** Both use `Arrays.sort()` internally, which uses a modified mergesort — O(n log n).

## 11. Deque (Double Ended Queue)

- **Double Ended Queue** — insertion and removal can be done from **both ends**
- Extends Queue interface
- Hierarchy: `Collection → Queue → Deque`
- Implementations: **ArrayDeque**, **LinkedList**

### Deque Methods (beyond Collection & Queue):

|Operation|Front|Rear|
|---|---|---|
|**Insert**|`addFirst()` / `offerFirst()`|`addLast()` / `offerLast()`|
|**Remove**|`removeFirst()` / `pollFirst()`|`removeLast()` / `pollLast()`|
|**Peek**|`peekFirst()` / `getFirst()`|`peekLast()` / `getLast()`|

Using these methods you can implement both **Stack (LIFO)** and **Queue (FIFO)**.

---

## 12. ArrayDeque

- Implements both **Queue** and **Deque** interfaces
- **Resizable array** implementation
- **NOT thread-safe**

```java
ArrayDeque<Integer> deque = new ArrayDeque<>();
deque.addFirst(1);
deque.addLast(2);
deque.addFirst(0);
System.out.println(deque);  // [0, 1, 2]
```

**Time Complexity:**

- Add/remove at head or tail: O(1) amortised
- Remove O(n)

**Space Complexity:** O(n)

---

## 13. Vector

- Exactly same as ArrayList — elements can be accessed via index
- **Thread-safe** (synchronized)
- **Fail-safe** (does NOT throw ConcurrentModificationException)
- Less efficient than ArrayList as for each operation it does lock/unlock internally

```java
Vector<Integer> obj = new Vector<>();
obj.add(1, element_name);
System.out.println(obj.get(0));
```

||Collection Till Now|isThreadSafe|Maintains Insertion Order|Null Elements|Duplicates|Thread-safe|
|---|---|---|---|---|---|---|
|**Vector**|Yes|Yes|Yes|Yes|Yes|N/A|

---

## 14. Stack

- Represents **LIFO** (Last In, First Out) operation
- Since it **extends Vector**, its methods are also **Synchronized** (thread-safe)
- How it differs from Deque: **Deque is NOT thread-safe, Stack is**

```java
Stack<Integer> stack = new Stack<>();
stack.push(item 1);
stack.push(item 2);
System.out.println(stack.pop());  // returns and removes top element
```

**Time Complexity:**

- Insertion: O(1)
- Deletion: O(1)
- Search: O(n)

**Space Complexity:** O(n)

## 16. Quick-Reference Cheat Sheet

```
Interfaces hierarchy:
  Iterable → Collection → List / Queue / Set
  Map (separate — does NOT extend Collection)

List → ordered, duplicates allowed, index-based access
Queue → FIFO; add/offer to rear, remove/poll from front
Deque → both ends; can act as Stack or Queue
Set → no duplicates (covered separately)
Map → key-value pairs (covered separately)

Key implementations:
  ArrayList    → dynamic array, fast get O(1), not thread-safe
  LinkedList   → doubly linked, fast insert/remove at ends, implements List+Deque
  PriorityQueue→ heap-based, natural order or Comparator; NOT FIFO
  ArrayDeque   → resizable array Deque, faster than Stack/LinkedList for deque ops
  Vector       → like ArrayList but thread-safe (synchronized)
  Stack        → LIFO, extends Vector, thread-safe

Comparator vs Comparable:
  Comparable  → class implements it, single natural order, compareTo()
  Comparator  → external class or lambda, multiple orders, compare()

Exception-safe method pairs:
  add()    throws exception ↔ offer()   returns false
  remove() throws exception ↔ poll()    returns null
  element()throws exception ↔ peek()    returns null
```

## 17. Common Interview Questions

**Q: What is the difference between Collection and Collections?**

> `Collection` is an interface that represents a group of objects and defines methods like `add()`, `remove()`, `size()`. `Collections` is a utility class with static helper methods like `sort()`, `shuffle()`, `reverse()`, `min()`, `max()`.

**Q: What is the difference between ArrayList and LinkedList?**

> `ArrayList` is backed by a dynamic array — fast random access O(1) but slow insertion/removal at arbitrary positions O(n). `LinkedList` is a doubly linked list — slow random access O(n) but fast insert/remove at head or tail O(1). `LinkedList` also implements `Deque`.

**Q: What is the difference between ArrayList and Vector?**

> Both are dynamic array implementations. `Vector` is **synchronized** (thread-safe) and fail-safe, but slower due to locking overhead. `ArrayList` is not synchronized but faster for single-threaded use.

**Q: What is the difference between `add()` and `offer()` in Queue?**

> Both insert an element. `add()` throws an `IllegalStateException` if the insert fails (e.g. capacity exceeded). `offer()`returns `false` instead of throwing — safer for capacity-restricted queues.

**Q: What is the difference between `poll()` and `remove()` in Queue?**

> Both remove the head. `remove()` throws `NoSuchElementException` if the queue is empty. `poll()` returns `null` instead — safer to use in most cases.

**Q: What is the difference between Stack and Deque?**

> `Stack` extends `Vector` so it is **thread-safe** (synchronized). `Deque` (e.g., `ArrayDeque`) is **not thread-safe** but is faster. For new code, it is generally recommended to use `ArrayDeque` instead of `Stack` for LIFO operations unless thread safety is needed.

**Q: What is the difference between Comparable and Comparator?**

> `Comparable` is implemented by the class itself using `compareTo()` — it defines the natural ordering and modifies the class. `Comparator` is an external sorting strategy using `compare()` — it doesn't modify the class and allows multiple different sort orders.

**Q: What is a PriorityQueue and how does it order elements?**

> A `PriorityQueue` orders elements by natural ordering (min-heap by default) or by a custom `Comparator` provided at construction time. It does NOT follow FIFO — the element with the highest priority (lowest value by default) is always at the head.

**Q: Why should you prefer ArrayDeque over Stack?**

> `ArrayDeque` is faster (no synchronization overhead), more memory-efficient, and more complete as a Deque implementation. `Stack` is considered legacy — the Java docs themselves recommend using a `Deque`implementation instead.
